# AI 手办固件产品需求

> v0.3 · 2026-10-11。现有能力依据仓库固定提交 `69312fd87564579bb28825719000a9b952dad46c` 的源码；下述目标和行为是产品需求，具体实现方案待评估。

## 1. 产品目标

1. **桌面互动**：手办插 USB 放在桌面时，空闲保持网络可达。用户在 App 发起明确操作，实体能接收并作出语音反应。
2. **随身使用**：手办使用电池供电，有已配置 WiFi 或手机热点时能够互动；失网、低电量、休眠和恢复有清晰表现。
3. **场景触发**：通过用户参与的游戏和日常事件，让角色在合适的时机开口。触发原因可理解，用户允许错过内容，事件与按键问答共同构成互动。
4. **能量与控制**：App 根据真实供电状态呈现“能量”和接电源动画，提供实际生效的实体音量调整。角色玩法能量与实体电量分别定义。
5. **持续更新**：设备后续能够通过网络升级固件，使新的互动能力和故障修复可交付给已有设备。

**角色、设备与账号的关系**：用户账号持有云端角色与档案，实体是角色语音和物理交互的载体；App 承接展示、参与和控制。账号绑定确认控制权，网络配置提供通信条件，设备执行回执确认实际结果。

## 2. 分项需求

### F01 — 工作模式、联网待机和深睡

**目标**：在不改变现板的前提下提供联网待机可行方案。建议评估两个模式，默认与开放方式由产品后续确认：

- 桌面模式：USB 供电空闲时仍保持业务网络连接；音频未使用时关闭功放和录音，不能仅因 20 分钟闲置失联。拔 USB 后按确认的电池策略切换。
- 电池模式：允许节能深睡，保留低压保护、按键唤醒及清晰的不可远程接收边界；可选联网待机是否开放需实测续航后决定。

需要评估“仅保持在线”“WiFi Modem-sleep”“自动 Light-sleep + 电源管理”的可行性、耗电和响应差异。当前 WIFI_SLEEP_OFF=true、常驻轮询、音频/驱动锁均需检查；自动 Light-sleep 不能通过直接强制 sleep 阻断 WiFi 来代替。

必须保留：低电量/ADC 异常处理、按键唤醒无循环重启、音频时钟与功放安全关闭。网络心跳不冒充用户活动；重连需退避，热点断开不能无限高耗电循环。

**验收**：桌面模式超过 20 分钟仍能从云端收到有权限的请求；USB 插拔、低压、断网/热点恢复、正在录音/播放时切换、休眠后按键启动行为正确。实测运行/联网待机/深睡整板电流、事件响应延迟和电池续航，报告环境与音量。数值门槛由评估后共同冻结，不凭芯片典型值承诺整机续航。

**产品解释**：联网待机是“没有正在说话，但仍能接收请求”。深睡是停止网络接收，用户需按实体键恢复。两种状态必须分别呈现；联网待机收到远程请求后的恢复处理，不描述为深睡唤醒。桌面与电池模式的默认规则需结合实测确认。

### F02 — 场景事件播放与 App 远程互动

**目标**：设备在线空闲时能够接受与语音问答独立的场景播放请求，包括 App 用户点击、游戏结果或用户允许的日常 hook。不能伪造按键回合绕过现有 WAITING 限制。

评估是否设计最小事件入口与状态转换，或复用现有 PCM 接收/播放能力。至少明确事件唯一标识、有效期、当前设备能力、音频开始/结束与本次事件的关联。

- App → 云端确认归属 → 设备接收 → 接受/拒绝 → 播放开始 → 完成/失败/被打断。
- 用户按键优先，录音、配网、升级和低压保护不能被事件抢占。
- 重复请求/重连重发不重复开口；旧事件音频不能串入新录音或问答。
- 手动远程操作离线及时失败，不在很久后意外播放；日常内容是否等待下次连接由业务类型决定，过期事件跳过。
- 保留静默时段与限频能力：业务规则可由云端负责，设备负责执行边界/有效性。不要硬编码具体游戏剧情进固件。

**验收**：空闲在线可播放；按键打断/录音优先正常；重复、过期、并发事件、音频中断、断网重连、低压停机有明确最终结果。App 不把“请求已发出”显示为“实体已说完”。

**产品解释**：hook 是有明确原因的一次场景反应，例如用户在 App 完成小游戏后让实体说一句结果，或参与日常事件后收到一句回应。它与按住按键进行的语音问答是两条入口。用户不参与、设备离线或事件已过期时，应按该场景规则跳过或稍后领取，避免旧消息突然播放。

### F03 — 设备状态、供电与能量显示的数据基础

**目标**：让云端/App 获得可信设备状态，固件提供实体供电数据，角色玩法能量由云端管理。

需评估：固件版本、硬件型号/协议能力、业务就绪、VBAT 毫伏值及读数有效性、USB 检测、低压保护/准备睡眠原因；必要的故障原因。定义变化上报、低频周期、采样/服务端更新时间与重连补报策略，避免高频增加耗电。

- 电池读数不能直接当成百分比；USB 且未装电池时读数无意义。
- 当前电路不能确认正在充电/充满，不输出未经验证的 charging/full 状态。USB 标记可支撑“已接电源”补能动画。
- “能量”是 App 的呈现层；实体真实状态与云端玩法数值分开。
- 入睡前可尽力上报，但云端失联原因不能仅靠断线可靠确定；缓存过期显示未知，不能持续显示旧“在线”。

**验收**：ADC 与万用表对照、充电/播放负载压降、USB 无电池、失效读数、重连与过期数据正确；上报不泄露 WiFi 密码或设备 PSK。

**产品解释**：“设备能量”是对实体供电情况的角色化显示，例如低能量或已接电源；如以后引入游戏消耗的角色能量，由云端玩法另行定义。补能动画必须表达收到的真实状态：只知道 USB 已接入时，表示“接电源”，不能表示电池已充满。读数未知或过期时不猜测数值。

**现有源码**：[power.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/power.cpp)、[power.h](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/power.h)、[config.h](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/config.h)、[main.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/main.cpp)、[proto.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/proto.cpp)。

### F04 — 可操作音量滑杆

**目标**：App 能调节真实设备音量并看到确认结果，重启后恢复。

建议云端转发已有 WSS 控制；如果建议 BLE 本地控制，请另列新增服务与成本，不能使用配网端点强塞指令。

需要：请求标识/顺序、输入校验、实际应用值回执、安全上限、超时/离线失败、NVS 持久化和启动恢复。App 0–100% 与底层增益的映射需新板标定；软件最大 256 不等于安全最大音量。拖动过程合并请求，松手/稳定后保存，不每次变化写 Flash。

**验收**：静音、可用最大值、失真/压降、播放中平滑变化、连续拖动顺序、重复指令、掉线、重启保留和默认恢复。若硬件最大输出不可满足需求，给出量测证据和单独硬件建议。

**产品解释**：这里的滑杆控制实体扬声器，不是手机媒体音量。用户拖动后应看到设备实际接受的音量；设备离线、拒绝或超时时，界面保留已确认值并说明调整未完成。默认值与最大值以新板听感和供电测试为准。

### F05 — 本地固件定时能力，再进行云端联调

**目标**：固件先具备可独立验证的计划管理、到时执行、休眠唤醒及恢复能力，再接入云端下发与 App 操作。前期可通过开发测试入口注入计划、模拟时间和预置音频验证，不依赖真实云端调度；测试入口与正式产品控制入口分开。

#### F05.1 本地计划管理

- 固件支持接收、保存、查询、修改和取消计划；每个计划具有稳定标识、修订版本、触发条件、有效期与内容关联。
- 同一计划重复导入不重复创建；新版本替换旧版本，晚到的旧版本不恢复已修改/取消的计划。
- 计划和必要执行记录有容量上限。保存成功后确认，容量不足或存储失败明确拒绝；取消结果可查询，不能只修改内存而在重启后重新出现。
- 计划执行完成或过期后按约定清理，保留必要去重/恢复记录；具体容量和保留期限由固件评估后确定。

#### F05.2 时间与重启恢复

- 区分相对定时（如十分钟后）和绝对定时（如今晚八点）；固件判断执行时刻，云端/App负责将用户时区与日程含义转成明确的执行时间。
- 固件记录时间是否可信。校时、时间向前/向后跳变、计时回绕不导致重复或无依据的提前执行。
- 相对定时不能在每次重启后无条件重新倒数；绝对定时在时间失效时不猜测时刻。断电后无法恢复可信时间的计划先标记等待校时，再判断执行或过期。
- 重启/深睡恢复时加载计划与执行记录，判断待执行、过期、取消和执行被中断；对播放中断不确定是否播完的情况，默认不自动整段重播，具体恢复策略按场景确定。

#### F05.3 定时唤醒与电源策略

- 本地有效计划需要在深睡后执行时，固件设置 RTC 定时唤醒，唤醒后重新判断时间、计划版本、有效期和供电条件。定时唤醒与现有按键唤醒共同工作。
- 无有效计划时按工作模式休眠；修改/取消计划后重新计算最近唤醒时刻，避免已取消计划仍反复唤醒。
- 低电量保护优先于计划执行，不能通过定时唤醒绕过恢复门槛。记录因低电量跳过的结果，避免反复醒来消耗电池。
- 用户按键唤醒后仍能正常启动与录音；定时执行结束后是否回到联网待机或深睡，遵循 F01 的模式与实际活动。

#### F05.4 本地执行与音频准备

- 定时模块调用 F02 的事件执行入口，不另建一套冲突的播放状态机；录音、配网、升级和保护状态的执行规则一致。
- 离线执行必须已有可用内容。前期使用固件测试资源/预置音频验证，产品内容缓存需明确格式、大小、完整性、容量及回收规则。
- 内容不存在、损坏或仅有云端引用时，明确返回内容未就绪；仅在计划允许且设备能够联网时取内容。超时或过期则结束，避免无限等待。
- 本地记录接受、待执行、执行开始、完成、失败、取消、过期/跳过等适用状态；到时一次执行，重复触发不会重复开口。

#### F05.5 本地验证先完成

用可控测试计划与预置音频覆盖：创建/查询/更新/取消、重复与乱序、容量/存储失败、相对/绝对时间、校时跳变、重启/断电、深睡定时唤醒、低压、按键并发、内容缺失和过期。测试记录实际触发偏差、唤醒耗电与计划/缓存占用。时间精度与容量门槛评估后确定。

本地能力通过后，再验证真实云端日程；本地注入或模拟测试不标记云端链路已完成。

#### F05.6 云端与 App 联调

1. 云端/App 创建计划，设备确认实际保存，App 再显示已设置；网络下发成功不等于设备保存成功。
2. 联调更新/取消、重复重发与乱序。云端和设备同步计划版本与最终结果，取消失败不能显示已取消。
3. 设备离线后恢复，核对有效计划、取消记录与执行结果；不批量播放积压的过期内容。
4. 验证云端校时/内容交付与设备定时执行；本地缓存内容在失网时按规则执行，缺少内容时按约定失败或跳过。
5. 覆盖账号归属变化、低电量、深睡唤醒、忙态与超时，App 显示真实结果。

**产品解释**：这里先实现设备自己的“记住计划、到点判断、满足条件执行”，云端负责用户日程、内容与下发。云端在指定时间直接请求在线设备播放属于 F02 的在线事件路径；F05 的本地计划用于需要设备提前保存并自行执行的场景。手机通知与实体定时执行分别确认。

### F06 — 保持 BLE 配网兼容与恢复体验

**目标**：保留 iOS/微信小程序当前配网协议；Android 按同协议接入。

保留原 UUID/广播/Security1/NVS 兼容；验证配网成功重启前手机能正确观察结果、错误密码后的重新设置、长 SSID/密码、配网中断恢复、已保存凭据的启动重连。

区分 WiFi 连接成功与 WSS 业务 ready；App 最终显示网络配置成功不冒充账号绑定成功。配网时暂停冲突任务，离开配网后释放 BLE 资源是否影响待机请评估。

**验收**：官方配网客户端、iPhone 与 Android/小程序分别记录结果；覆盖长输入边界、拒绝无效编码/超长输入、正常重启断连和 NVS 保留。无 PoP 的安全/归属验证缺口单独列入 F07 评估，不仅凭 BLE 握手认定所有权。

**产品解释**：配网是把家庭 WiFi 或手机热点的信息交给设备，让它以后自己联网。流程需分别告诉用户“网络配置成功”“服务连接成功”“账号绑定成功”，避免一次成功提示掩盖后续连接失败。Security 1 是现有加密会话，PoP 指设备持有证明；当前配网没有 PoP。

### F07 — 云端账号绑定所需的设备身份支持

账号、设备归属、角色/记忆/玩法数据以云端为准。设备不保存完整用户账号密码或档案；家庭 WiFi 密码默认不上传云端。

请评估现有 DEVICE_ID/TLS-PSK 是否可以支撑唯一设备认证，以及出厂序列号/二维码、每设备凭据注入、认领的在场证明/验证路径。账号认领/解绑由云端鉴权执行，不能看到 SN 就无条件获得控制权限。

需要明确 WiFi 重配、账号解绑/转让与恢复出厂分别删除什么；解除绑定不等于删除云端角色记忆；App 用户 token 不作为设备 PSK。

服务器地址/PSK 当前在 secrets.h 固定；是否需要远程/本地配置与密钥轮换请列为单独可行性项，不在现有配网成功中隐含实现。不要让评估报告包含实际生产密钥。

**验收**：合法用户与设备匹配，越权拒绝，解绑后旧账号不能下发控制，重新配网不意外改变归属，凭据异常可诊断。固件仅承担必要身份能力，云端账号体系由服务端负责。

**产品解释**：绑定回答“这台实体由哪个账号控制”，WiFi 配置回答“实体如何上网”。同一台设备更换 WiFi 不应更换主人；用户解绑实体后，云端角色和档案按账号规则保留。设备身份凭据用于证明设备本身，用户登录凭据用于证明用户，二者职责分开。

**现有源码**：[secrets.h.example](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/secrets.h.example)、[net_wifi.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/net_wifi.cpp)、[net_ws.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/net_ws.cpp)、[transport.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/transport.cpp)、[proto.cpp](https://github.com/elin66alpha/AI_figure/blob/69312fd87564579bb28825719000a9b952dad46c/firmware/ESP32C3_AI_Voice/proto.cpp)。

### F08 — 完整 OTA 升级能力

**目标**：现板联网更新固件，减少之后拆机烧录；利用已有双槽，不要求先做蓝牙 OTA。

需要评估设备 HTTPS 拉取镜像、版本/硬件匹配、可信来源/完整性验证、写非运行槽、切换启动、启动健康确认和失败回滚。App/云端负责发起权限、版本信息与状态呈现，具体下载/升级协议另行联合冻结。

限制：供电不足/电池过低拒绝升级，录音/播放冲突时延期；失败保留可启动旧镜像，升级后 NVS 迁移受控。进度需区分下载、写入、重启、健康确认，不能显示 100% 下载就等于升级完成。

当前双槽各 1.875MiB；新增功能与 OTA 库必须报告镜像大小和余量。首次从旧 Arduino 分区迁移涉及引导程序/分区表，单独制定 USB 烧录路径，不能默认常规应用 OTA 覆盖。

**验收**：错误型号/版本/损坏镜像拒绝、下载中断/写入中断/启动失败恢复、健康确认与回滚实机演示；断电测试按可恢复的测试设备/方案进行。评估是否启用签名/Secure Boot 的具体策略和生产影响，不能将下载哈希校验等同来源认证。

**产品解释**：OTA 是联网更新实体固件。当前运行槽 A 时，将新版写入 B，确认可用后切换；下一次反向使用。双槽的价值是让后续功能升级和修复减少拆机烧录，并为失败恢复提供基础。另一槽存在本身不等于下载、健康检查或自动回滚已实现。

### F09 — 便携与整机基础验证

**目标**：核验电池供电、手机热点、现有音频主路径及安装示意结构的工作条件。

覆盖：热点配置/重连、外出失网退避、不同音量下续航/温升/电压、按键唤醒与携带误触、PDM 位序/增益/声压、NS4168 播放/打断、ADC 校准、整板深睡/联网待机电流。

## 3. 联合契约要求

联合契约明确设备、云端与 App 对同一操作的职责、请求含义和结果。先用本地测试输入/输出验证固件，再使用相同语义进行云端联调；具体 JSON、字段名、接口地址和超时数值在评估后共同确定。以下是需求，不表示当前源码已具备这些能力。

### 3.1 三端职责与事实归属

| 对象/操作 | 本地固件 | 云端服务 | App |
|---|---|---|---|
| 能力与版本 | 上报硬件/固件及实际支持能力 | 保存能力与兼容信息 | 按能力开放功能 |
| 状态与能量 | 采样并标记有效性、供电与本地状态 | 保存最近状态，判定连接/数据是否过期 | 呈现真实或未知状态 |
| 场景播放 | 接受/拒绝、执行、打断、返回结果 | 校验归属，生成内容，路由与管理有效期 | 发起互动，显示设备确认结果 |
| 本地计划 | 保存实际计划，定时判断、唤醒、执行与记录 | 保存用户期望日程，下发修订与内容，同步结果 | 创建/修改/取消，区分同步中与已生效 |
| 音量 | 应用有界值、回执、保存与恢复 | 授权和转发，保存确认状态 | 节流发送，显示实际值 |
| 身份与绑定 | 证明设备身份，执行有效授权请求 | 管理用户、归属、认领/解绑与权限撤销 | 登录和绑定操作 |
| 升级 | 下载/校验、写槽、重启、健康确认与结果 | 发布适配版本，授权并记录升级 | 发起操作，呈现过程与最终结果 |

云端“期望的计划/音量”和设备“实际保存的计划/音量”分别记录。实体状态与执行结果以设备回执为依据；用户账号、归属及日程意图以云端为依据，App 不自行把未确认操作当作生效。

### 3.2 指令、状态上报与执行回执

- **指令**：描述让哪台设备做什么，关联稳定请求标识、适用版本/计划修订及必要的有效期；设备先检查身份、能力、参数和执行条件。
- **状态上报**：描述实际观测，例如电压/USB、时间有效性、当前计划版本或播放状态；具备采样/接收时间语义，未知与旧数据可识别。
- **执行回执**：关联原请求及实际结果，区分设备接收、保存/应用成功、执行开始与最终结果。重复查询或重试返回可关联的结果。
- 固件错误应明确为不支持、输入无效、过期、忙、低电量、内容未就绪、存储失败或执行失败等可处理原因；云端离线/超时不伪装成设备主动拒绝。

**产品解释**：收到消息不代表完成动作。例如“计划已保存”只是设置成功；到时“播放完成”才是本次行为完成。升级下载完成也不代表新版启动通过。

### 3.3 各功能的成功与失败含义

| 操作 | 何时可以显示生效/完成 | 需要明确的失败或中间状态 |
|---|---|---|
| 立即场景播放 | 设备确认开始/结束分别更新状态 | 离线、忙、过期、内容缺失、播放被打断 |
| 设置/修改本地计划 | 设备确认保存对应修订 | 待同步、时间未就绪、容量/存储失败 |
| 取消本地计划 | 设备确认停止未来执行并保存取消结果 | 取消待同步、已执行、正在执行且未能停止 |
| 调节音量 | 设备回报实际应用值；保存状态按需要单独确认 | 超时、离线、限幅、保存失败 |
| WiFi/绑定 | 网络配置、业务 ready、云端归属分别确认 | 配网失败、正常重启断连、服务未连接、认领失败 |
| 固件升级 | 新固件完成约定健康确认 | 下载中/校验/写入/重启、失败、回滚/待恢复 |

等待超时表示“结果尚未确认”，不是确定没执行；查询/重连同步获得最终结果。App 可提示重试，但同一操作重试保留关联标识以避免重复执行。

### 3.4 重复、乱序、取消与重启恢复

- 同一指令重复交付仅产生一次有效操作；去重范围、记录容量与保留时间共同确定。
- 计划修订有顺序，旧计划不能覆盖新版本或取消记录；音量旧回执不能覆盖最新操作。
- 取消与执行发生竞争时，由设备确认当前状态，返回已取消、已完成或停止失败等真实结果；不承诺所有取消都能撤回已经发出的声音。
- 保存的计划与执行记录恢复后按状态处理。掉电发生在播放或回执阶段时可能无法证明已经播完，应保留“执行中断/结果未确认”的含义，并按场景恢复规则处理，不宣称任何异常下都能严格只播一次。
- 用户主动重试、自动重发和新的一次互动分别识别，避免把用户再次操作误当旧重复请求。

### 3.5 忙态、队列与执行优先级

1. 低电量和必要保护优先。录音期间不强行插入场景音频；播放中按键沿用打断规则。
2. 配网、升级与播放/计划的冲突明确拒绝或有界延期。OTA 写入/启动切换等关键阶段不能被普通按键当作语音打断而中止，升级前后另行定义可操作时机。
3. 队列容量、有效期和等待期限有限。手动互动超时后不突然补播；定时内容错过后按既定跳过/领取规则处理。
4. 同一计划只有一个明确执行方：云端直接触发或设备本地定时；若存在冗余交付，使用同一事件关联去重，避免两端同时触发两次。

### 3.6 离线、时间与状态同步

- 在线连接、业务 ready、深睡、失联和读数过期分别表达；缺少设备原因时只显示未连接。
- 深睡中即时指令不承诺可达。已保存的本地计划可按 F05 独立执行；尚未同步的计划不能显示已在设备生效。
- 重连同步设备能力、当前状态、实际音量、计划修订及未确认结果；先处理过期/取消，再决定有效任务。
- 断电或校时失败后，设备能报告时间不可信。云端/App 不把“已下发时间”当成“设备已完成校时”。
- 解绑后拒绝旧账号的新请求；已缓存本地计划在离线情况下的归属有效期、撤销与清理规则需约定，不能承诺离线设备即时收到云端撤销。

### 3.7 验证顺序与联调用例

**第一步，本地固件验证**：使用与正式契约相同含义的测试输入，覆盖有效/无效指令、去重、乱序、保存/取消、忙态、低压、重启/深睡、音频缺失和计划到时执行，验证回执与实际声音一致。

**第二步，云端与设备联调**：核对身份与能力、下发与确认、重发/掉线/恢复、计划更新取消、内容交付、过期和实际结果；验证云端期望状态与设备实际状态收敛。

**第三步，App 端到端验证**：操作后只在相应确认时显示成功；覆盖“设置计划成功但内容未就绪”“网络超时但设备已执行”“取消时已开始播放”“离线后计划尚未同步”“升级回滚”等用户可见分支。

旧设备未支持新增能力时呈现不可用；新增协议不能破坏原有 BLE 配网、按键问答与打断。所有测试都以对应固定源码版本、实物状态与回执记录核对。
