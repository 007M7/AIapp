# 后台运行、发布与回退

2026-10-12 · Linux 单机目标，模板已准备；本轮没有执行线上部署。

## 配置和部署

1. 固定源码提交、Python 锁文件与 package-lock，CI `npm ci && npm run build` 和后端测试；构建 dist 随部署包交付，不当源码。
2. 在 Linux 创建独立 aiapp 系统账号，工程只读；管理 data 目录仅该账号可读写。Python 3.12 与虚拟环境；Nginx TLS 同源代理，API仅环回8787，语音网关保留独立 systemd 和 stunnel。
3. 使用 `/etc/aiapp-management.env` 配置 `MANAGEMENT_HOST=实际管理域名`，权限600；模板不启用 --local-preview。同一正式 data 目录先执行 --create-admin 引导真实账号，密码交互输入。
4. 启动前完成 SSO/MFA 或等效隔离访问、账号权限复核、素材解码／扫描、证书和资产来源审查。模板域名、证书必须替换，PSK/HTTPS 443 复用按既有 nginx SNI 方案协调，不能覆盖设备入口。
5. `/health` 及 journal 监测存活、500／锁失败、请求耗时；操作记录查发布和事件结果。记录实测吞吐和延迟，负责人待指定；本轮未配置外部告警服务。

目前不自动信任 X-Forwarded-For，登录限流在反代后按 loopback 共享计数；真实多用户部署需在 Nginx 按可信客户端地址增加登录限流并验收。高并发素材文件IO、数据库锁竞争、生产长任务及恶意素材仍需测试。

## 备份与恢复

运行 `python admin/server.py --data <管理数据目录> --backup <备份文件>`，通过 SQLite backup API 获得一致快照。备份 DB＋blobs 一起形成有日期的快照，校验数据库 integrity_check 和发布清单所有素材哈希；建议本地7份、隔离备份30份，实际保留期需运营确认，凭证不得与明文备份共存。数据包含管理员密码散列与操作记录，按敏感资料保护。

恢复先暂停写入／停管理进程，保存当前完整数据副本，再恢复数据库和素材，核对 schema_version、外键、发布清单与哈希后启动；实际内容回退用 channel 历史指针，不倒退整个数据库。代码回退保持 schema v1 兼容；未来破坏性迁移先备份和演练，禁止自动降级删表。

## 事故处置与门禁

异常发布：先下架环境阻止新执行，查 request_id／审核／版本引用，再回退历史发布。账号泄露：停用账号撤销会话，查操作记录，轮换访问凭证。素材损坏：停止该发布消费，恢复对应哈希文件并核验。设备执行失败：未接入阶段不可承诺播放；未来以网关完成回执为准。

本地验收为可运行、可验证。生产准入需要 Linux部署／TLS、账号与权限、扫描、恢复、性能、告警及 App／设备接口逐项留证；不得从本地测试结果推断已可商用。
