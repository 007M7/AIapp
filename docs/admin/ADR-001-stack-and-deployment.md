## 事实与约束

用户确认：单台 Linux 云服务器，沿用现有团队。现有设备服务为 Python，`server/requirements.txt` 已使用 aiohttp 与 websockets，后端设计 14 明确 API 使用 aiohttp。现有 root Node 工具零依赖、小程序 CommonJS、iOS SwiftUI；没有现成管理前端。当前本机 Python 3.12.14、Node 24.16.0；云服务器实际内存、发行版和当前并发未重新测量，旧稿 2C2G 不是本轮实测。

新增后台范围含跨角色审批、素材上传、历史版本、发布指针、回退、操作记录。这已超出静态 HTML demo；语言选择围绕团队复用与维护，不由本地示例代码倒推。

## 对比与决定

| 领域／方案 | 实际收益 | 代价／判断 |
|---|---|---|
| Python + aiohttp | 复用现有语言、依赖、异步 HTTP 和 Linux 运行方式 | 沿用；API／领域规则明确分层，同步 DB 工作不占事件循环 |
| FastAPI | 类型校验、API 文档便利 | 多引框架且改变已定方向，本期无必要；契约可由现有领域校验明确维护 |
| Node/Nest 或 Java | 成熟企业后台生态 | 现有设备服务没有这些栈；增加后端维护面，本期不选 |
| 标准库 HTTP | 本地试验成本低 | 不能承接正式服务器选型；已替换为 aiohttp |
| Vue 3 + TypeScript + Vite | 表单／权限／版本状态组件化，编译类型检查，静态部署简单 | 新增独立前端工具链，维护人员需掌握 Vue；比维护大型原生 DOM 脚本更适合此范围 |
| React 或重型 SSR | 可实现同样 UI | 无已有 React/SSR 项目可复用，内部管理无 SEO 需求；本期不引入 |
| SQLite WAL | 少量运营人员、单机、事务与备份简单 | 单写者，文件不可多机共享；首期适用，需看锁等待指标 |
| PostgreSQL | 多实例、高并发写、成熟数据库治理 | 增加服务与运维；多实例、跨业务事务或写竞争实测超标后迁移 |
| Nginx + systemd | 复用既有部署方式，TLS 入口、非特权进程、分服务隔离 | 选用；无需先引 Kubernetes 或复杂消息中间件 |

前端 `type:module` 仅位于 admin/frontend/package.json，不影响 root 与小程序。根工具仍无 npm 依赖，新增后台有独立 package-lock 和 requirements-lock；Node 只在构建时需要，云端运行无需 Node 常驻。

## 扩展与迁移条件

当前只管理生产内容事实，不让后台另建真实用户资产数据库。未来 App 业务服务通过稳定发布快照和授权管理接口接入。真实设备网关通过独立命令／回执契约连接，不能共享未经定义的表直接写状态。

需要两个 API 写实例、业务多租户／大量 App 写请求、持续 SQLITE_BUSY 或发布／保存延迟实测不满足目标时评估 PostgreSQL。建议测试目标为后台写 p95 <200ms、锁失败率 <1%；是初期验收目标，未声称生产实测已达标。数据迁移需版本校验、引用完整性、双读对照、备份恢复演练与维护窗口，不把更换数据库只当连接串改动。

调度器在具备真实事件消费者后增加：首期单实例可用数据库任务表及独立 systemd worker；实测吞吐与可靠性不足再引队列。定时配置与测试执行不能替代调度验收。

## 运行边界

开发预览身份只在 --local-preview 启用且限本机 Host；Linux 模板不启用此参数。真实账号、HTTPS 安全 Cookie、最小管理员权限、备份／素材恢复和设备契约是生产门槛。公网正式发布仍需 SSO/MFA 或等效访问控制、素材扫描、权限复核和监控告警；本轮先做到本地可运行与可验证。
