### 0.2 五条红线(违反即拒审/拒合并)

1. **平台外零进出**:无公开协议、无开放 API、无自带 key、无局域网直连、角色包/外观包无平台外导入导出。用户**个人数据**(记忆/对话原文)的平台外可导出性是另一件事,归账号/合规线按个保法与停服承诺裁决(N-11),与包的禁令无关。
2. **包内零可执行、零音频文件、零外部引用**;音色只允许平台白名单枚举值。
3. **`relation_state` 禁止出现任何"好感度/亲密度"数值字段**;永不卖成长速度。
4. **`memory_op` 计量权重恒 0**(记忆永不进付费口径);免费档数值不设痛感,待 Q-19/Q-42。
5. **主动开口三触发白名单默认全关**;不做未成年人向、不做心理治疗话术。

### 0.3 三个最容易踩的坑(都有代码实据)

- 出厂 `REPLY_MODE` 默认 `echo`(`config.py:95`)——不翻转,开箱=回放原声而日志一切正常。
- `MAX_CONNECTIONS=8` 是虚假容量(`config.py:67`)——百炼 TTS 并发 4 条即限流,实际约 3 台(SERVER.md §6.4)。
- 百炼免费额度 2026-10-01 到期、无预警(备忘录 §六)——不建监控与付费切换预案,服务会静默变哑。

## 1. 共同基线

### 1.1 设计公理(全文用它们过滤每一条设计)

1. **可玩性重于技术强大**。每个机制服务于"像给手办换角色卡一样简单",不是"像装插件一样强大";不上向量库、不做逐句同步审核、玩法必须在一次按键回合内交付完整乐趣——都是这条的落地。
2. **手办的价值是"摆在那儿"**:可玩性不是 DAU,是"每次互动它都像活的"。行业无人敢公开留存、"两周后急速下降,很多人第三个星期不再开机"(11 §0②,财新经 36氪转述)→ 按"偶发惊喜"而非"每日义务"设计。
3. **记忆不是付费点,是"它像个活物"的证明**(11 §0③/§4.2:芙崽把长期记忆放免费档永久免费,做到近 30 万台——公司 2026-07-13 Pre-A 公告口径,原文含"近"字,11 §1)。
4. **低置信度宁可不说**(07 T2:记错比记不住更毁信任);记忆必须可见/可编辑/一键清空(07 §3-T2 信任底线)。
5. **黏性建立在"听"上,不是"说"上**;别卖养成,卖连载;永不卖成长速度(07 §0.3/§4)。

### 1.2 与已否决方向的红线对照(复核确认六册无违反,此表为统一格式)

| 已否决方向(`08` §3.2、`09` D-09) | 本设计对应立场 |
|---|---|
| 面向极客的开放框架 / 高自由度定制 / 用户写规则 | 创作端是结构化表单向导,自由度封顶在表单字段 |
| 公开协议 / 开放 API 生态 | `figurepack/1` 是私有存储格式,不发布规范、不容许第三方实现 |
| 自带 API key | 音色/模型/密钥全部平台侧,包里只有白名单枚举值(Q-43 就此关闭) |
| 局域网直连 | 分发与启用全走服务器,设备永远只连我们的域名 |
| 插件商店(可执行扩展) | 包内零可执行内容、零音频文件、零外部引用 |

### 1.3 现状一句话(细节见 §5.1)

对话能力约 90%,产品运营能力约 5%(00 §3):零账号、零数据库、零 HTTP 接口;对话历史是进程内字典且键为设备自报 ID(`session.py:41,116`);人格是全局一个环境变量(`config.py:182-185`);`_chats` 进程重启清空(`llm.py:210`)。本文一切"新增"都长在这块地基上。

## 2. 设想一「一个核心多个外观」:角色/外观包系统

> 本章是"一个核心多个外观"数据模型的**唯一权威定义**(复核裁决:原草稿 1/3/4/5 各自为政,现统一到本章,其余章节只引用)。只设计数据格式与平台机制,**不含任何美术造型**(09 D-04:外观美工归设计团队);不设计付费墙(Q-20 未决)。

### 2.1 对象模型定稿(D2-1)

**决策:可分享单元 = 角色包 = 单一 JSON 信封 `figurepack/1`(元数据 + core + skins[])。**

- **core(魂)**:它是个什么性格的存在——人设、称呼、问候、记忆种子、**音色**、玩法仪式音效名。
- **skins[](身体)**:它用什么身体语言表达——LED 情绪语法、物理可换外壳 SKU 引用、展示素材引用。
- 一个核心挂 N 个外观;换外观不丢性格、换性格不换身材。
- 原草稿 4 的"角色包/外观包/组合包"三对象模型**不再采用**:skins 随信封走,审核面单一(一个包一次审)、无引用完整性问题;"组合包"降级为**商店策展概念**(官方把核心+外观搭配推荐),不是数据对象。原草稿 5 的 `role_cores/role_versions` 表名弃用,以 §5.3 的 `packs/pack_versions/characters` 为准。
- 数据格式顺着现有代码分层走,不发明新抽象:人格在服务端(`llm.py:216-217` system prompt 拼装、`session.py:41-48` 按设备存历史),表达在固件(`led.h:11-17` LED 模式枚举、`cue.h:28-32` 预定义提示音、`bubble.cpp:8-19` 等待音效参数)。

### 2.2 核心-外观归属总表(D2-2,复核 medium 裁决)

| 字段 | 归属 | 生效层 | 说明 |
|---|---|---|---|
| persona(结构化称呼/语气/口头禅/禁谈 + 限长自由文本) | **core** | A 纯服务端 | 结构化优先于自由文本 |
| memory_seed(初始认知设定,≤300 字) | **core** | A | 装包后归用户、用户可改 |
| greeting(初见/重逢台词) | **core** | A(首回合前置形态) | 开机主动说需固件 G1,后置 |
| **voice(音色/语速)** | **core** | A(改造成按会话读后) | 限定款换声(外观级音色覆盖)V1 不做;日后做则 skin 覆盖 core 且受白名单约束 |
| **玩法仪式音效/口头短音 cue 名**(游戏开始/胶囊投递/扭蛋出货等,G4 新增) | **core** | B(老固件静默忽略) | 沿用草稿 3 G4 口径:"音效属于角色卡的魂,不是外观" |

### 2.5 版本化与兼容(D2-4)

1. **格式层**:`figurepack/1` 只做加法演进(新增可选字段),永不改语义、永不删字段。
2. **包层**:semver。major = persona/memory_seed 破坏性变化(老用户**不静默升级**,小程序弹确认);minor=增量;patch=文案纠错。文本字段变更按 diff 触发重审(§2.6)。
3. **设备能力层**:包与 skin 各带 `requires: [能力令牌]`(`led_v2`/`cue_v2`/`proactive_v1`);服务端按 `hello` 上报的 fw(`proto.cpp:49-50`)查能力表;设备不支持 → **自动降级到默认外观并在商店页标注,绝不阻断安装**。

"未知即忽略"是现有协议约定,三个层面都成立(逐行核对):未知消息类型固件 `default:` 分支忽略(session.cpp:130-131);未知 cue 名忽略(session.cpp:119-121);未知 JSON 键天然不读(手写按 key 查找的解析器,proto.cpp);服务端同样遵守。这条约定让**服务器永远先行**,老设备全程无感降级。开放问题:fw 字段现为自由字符串,需与固件线约定 semver 格式(N-04)。

### 2.6 上架流程与内容安全(D2-5/6/7/8)

**创作 = 小程序内结构化向导**(D-07"平民级"落地):作者填表单,JSON 全程不见。服务端校验:字段白名单、限长、**音色必须在平台已开通白名单内**(音色受厂商授权约束)、LED/cue 取值在服务端枚举内。

**为什么 V1 包是纯数据、零音频文件(刻意设计)**:语音一律由平台 TTS 按白名单音色合成。三重收益:① 审核只需过**文本**内容安全(不必碰音频 mediaCheck);② 绕开音频素材版权;③ 试听与问候预渲染,不占运行时 TTS 并发(§2.7)。

**prompt 注入防线**:
1. **拼装层(最重要)**:包不直接持有 system prompt。最终 prompt = **平台安全底座(永远置顶、不可覆盖)+ 角色段**;结构化字段优先于自由文本,自由文本带限长与分隔标记,显式声明"底座规则优先于角色设定"。作者无法把安全规则"人设掉"。
2. **输入侧(上架机审)**:禁 URL/联系方式/脚本片段;禁医疗、金融建议与心理治疗话术类人设;禁冒充真人/官方;未成年人向一律拒。
3. **输出侧(运行时)——两轮评审合并裁决**:原草稿的"逐句同步拦截"**不可落地**——现行流水线每切出一句立即送 TTS(pipeline.py:55-78 的 run_tts 内逐句 `synth`),句间空档超过设备约 300 ms 余量(pacer.py 的 BURST_MS 突发预算)即欠载断续,首句延迟也直接吃掉 1.2~2.1 s 预算。**V1 输出侧口径(最终合并裁决,与 §5.3/§3.7 三处统一)**:①不做逐句同步拦截;②**不逐回合送审对话**——对话原文不经社区、不强制送审(§3.7③),微信接口配额与费用未实测(N-02)前,逐回合送审是过度设计;③运行时防线=prompt 安全底座 + 用户举报 + **回合低频抽审**(audit_tasks,target_type=turn,采样率可配,官方与 UGC 包都抽);④最高风险面(UGC 人设文本)已在发布/分享时全量送审(§4.4)。**逐回合全量送审挂 M1 后再裁决**,门=N-01(同步/批量延迟实测)与 N-02(配额成本)双关闭;违规处置=事后下架/封包(设备端零动作,见下)。若未来必须同步拦截,限首句或整回合批量放行,且先实测单句延迟再写进设计(N-01)。

**下架即时生效且设备端零动作**:persona/音色/外观全在服务端下发,下架=服务端停用该包,设备下次会话自然回到默认角色——"角色活在服务器"直接换来的治理能力。

**治理节奏(复核裁决:整节为 UGC 开闸后才实现,M1)**:V1 落地最小集 = 官方 3~5 包 + per-device 激活 + 上架/发布时文本 msgSecCheck + 回合低频抽审(输出侧,见上)+ 社区总下架开关。人审阈值、发布频控、作者包数配额、fork 溯源、举报 SOP 全部**只留设计占位不写代码**(§4.4 给出设计,触发门=N-10/UGC 开闸)。

  → 选外观(若核心带多外观) → 生效:下一次按键说话即新角色

- **主视图是「我的收藏/我的角色」收藏册**,不是设备管理页(12 §2.2)。

## 3. 设想二「可迁移的记忆与可玩性」

### 3.1 用户/设备/角色:三者关系模型(D3-1)

| 实体 | 是什么 | 拥有什么 |
|---|---|---|
| **用户 user** | 微信登录的自然人(openid;App 后置走同主体 unionid 打通,微信平台机制待接入时核对) | 全部数据的所有权主体:名下设备、角色实例、记忆、用量 |
| **设备 device** | 手办的"身体":出厂 SN + PSK 身份 + 在场表达(喇叭/单色 LED/按键) | 只拥有运行时状态(当前激活角色、音量、固件版本);**不拥有任何记忆** |
| **角色 character** | 用户养的角色实例 = 角色包(引用某版本)+ 记忆 + 关系状态 | **记忆与关系状态的唯一归属** |

**决策 D3-1:记忆挂在"角色实例",不挂设备、也不直接挂用户。**
理由:① 换设备/换手机不丢"它记得你";② "换角色包=新角色从零开始"语义干净;③ 芙崽把长期记忆放免费档并做到近 30 万台(公司 2026-07 Pre-A 公告口径,11 §1;长期记忆免费机制见 11 §0③/§4.2,华为官方页口径、对憨憨、与芙崽同源)——记忆是"活物证明",必须跟人跟角色走。

- **一人多手办**:user → N 个 character,每台设备经 `device_runtime.active_character_id` 激活一个(语义见 D3-2)。
- **一手办多角色**:设备是舞台,角色是演员;切换=改指针,设备无感,零固件改动;切换入口只在小程序(设备无屏)。
- **顺手修掉现存坑**:今 `_chats` 以设备自报 dev 为键(`session.py:41`,`chat_for()` 见 `session.py:44-48`,回合组装处调用),两台设备报同一 ID 会共享上下文(00 §7-4)。键的改造分两步(§3.7 S1/S2)。
- **设备可信身份(D3-2)**:鉴权与数据分离——PSK 只管"能不能连上"(stunnel 终结 TLS 后 Python 拿不到 PSK identity,SERVER.md §7.3 已知缺口,保持不动),用户/角色归属全由服务器侧绑定表裁决;hello 的 dev 只做路由与日志。绑定流程依赖硬件线 Q-51(PoP)/Q-52(出厂 SN+二维码),均未做;数据模型先留 sn/psk_identity 字段。

### 3.2 第二只手办的 V1 总口径(D3-3,复核 medium 裁决——原三册互斥口径在此统一)

**同一角色,同一时刻,至多在一台设备上激活。**

- **第二只手办默认 = 新角色**(新记忆,新的一生);可选**"接手"**已有角色 = 一次性搬家(新设备激活同一 character,旧设备激活位清空)。数据层无并行读写问题。
- **并行分身**(同一记忆两实例并行成长)**不做**;**记忆摘要导出/导入**(给第二只手办"继承")**不做**——两者挂 Q-20(系列联动"买第二只记得你")后置,触发条件与 §5.6 M2 对齐(首批复购行为出现)。
- 收藏册视图按"我的角色"组织(12 §2.2);"接手"与"换新"的文案如何避免"它死了"的误读,归产品叙事。

### 3.3 记忆数据模型:三层(D3-4;表结构唯一权威在 §5.3)

1. **chat_turns(对话历史=原材料)**:每轮 user 原文(ASR 文本)、figure 回复全文、talk_ms、device_id、turn_seq。**不存音频**(16kHz PCM 只在回合内流过,落盘即隐私负债,Q-35 最小化)。**唯一显式例外=原声存档**(P7 时间胶囊、P10 送礼预录):独立对象存储(不入库、不进日志)、加密落盘、用途限定(仅投递给本人/指定收礼人)、默认保留期=到期投递后 30 天删除(参数挂 Q-35)、注销级联删除(M8)。近期热窗口进 prompt(现 `LLM_HISTORY_TURNS=10`,config.py:181,保持);`llm.py:209-241` 的进程内历史平移入库,`llm.py:210`"内存里存,不持久化"就此作废。**原文滚动保留(默认 90 天,占位值——与架构分册的 30 天差异已收敛为单一裁决项,挂 Q-35 定稿)**;到期删原文、保留抽取产物;用户可随时清空。保留期是磁盘护栏,不是付费点。
2. **memory_facts(事实画像="它记得你"的本体)**:fact_text、category、confidence、source_turn_id(可溯源)、salience、status(active/archived/hidden)、pinned(用户置顶,永不自动淘汰)。**turn_end 后异步抽取**——复核裁决:异步≠不挤占,抽取的 LLM 调用与实时回合共享同一事件循环、连接池与 2C2G 的 CPU。**S3 实现约束写死:抽取放独立 worker 进程(与网关/API 并列的第三个 systemd unit)或只做每日离峰批量;监控加"抽取开启前后首包延迟分位"对照作为门禁。** 冲突不覆盖:同主题新事实作为新行,由 confidence 与用户编辑裁决。prompt 取 top-k(salience × recency);**低置信度不进 prompt**。**系统自动淘汰才降权归档,用户主动删除=硬删**(逐条删除与按角色清空即时物理删除,其 source_turn 留在 chat_turns 随其过期自清;删除权口径作为显式裁决项并入 Q-35);软上限(建议 200 条/角色,待定)是工程质量护栏,淘汰=进"已淡忘"档案。
3. **relation_state(相处痕迹)**:称呼(及进化史)、用户偏好(静默时段/别提的事)、角色自己的事(在读什么、连载进度)、里程碑。不过期,跟随角色实例生死。**命名纪律:禁止出现"好感度/亲密度"字段**(07 §7②"幼稚过敏"生死线);这层存"可被念出来的相处事实",不是数值。

**组装公式**:`system = 平台安全底座 + 角色包 persona(当前版本)+ relation_state 摘要 + memory_facts top-k;messages = 最近 10 轮 chat_turns + 本轮输入`——即把全局 `LLM_SYSTEM_PROMPT`(`config.py:182-185`)换成按 character 组装,结构不动、延迟预算不动。音色同理:全局 `ALI_TTS_VOICE`(`config.py:118`)改按角色注入。V1 召回用 salience top-k,不上向量检索(单角色记忆总量小;明确后置)。

## 4. 设想三「社区」:分享与共同探索

### 4.1 边界三条线(D4-1)

1. **社区=平台内分享社区,不是开放生态。** "开源丰富强大的社区"在本平台的转译:**人人可创作、人人可分享、创作有署名、改编留链路——但一切发生在我们的小程序里**。分享单元=figurepack(§2),平台内许可、平台内分发,不提供协议级导出。
2. **社区不做社交图谱。** 无关注/粉丝/私信/陌生人语音;用户是来"给我的手办找新鲜事"的,不是来交朋友的。
3. **社区内容不改变硬件事实。** 分享物落到设备上只有三种表达:说话(回合制)、单色 LED、发声时机。

**地基现状**:零账号、零数据库、零 HTTP 接口——**社区是全新模块,不存在"先做社区再补地基"的路径**。

### 4.2 内容包模型(D4-2)

社区只交换一种容器:**figurepack**(§2 单信封,含 skins)。原草稿 4 的"外观包独立对象+组合包引用"不再采用(复核裁决,与 §2.1 对齐):skins 随包走,外观数量与形态待官方内容首发(D-A2 精神保留:格式未定稿前社区先行只会造出假格式)。公共字段:id / version / author(笔名+账号)/ fork_of(改编来源,平台强制保留)/ license=平台内使用 / status / audit 记录 / 计数(装载、点赞)。

**装载语义**:使用=复制一份到**我的角色库**(账号级,随人不随设备),再激活到某台手办;不覆盖、可回滚。复制式装载让"作者更新"变成显式动作而非强推,规避"我手办的性格半夜变了"的信任事故。

### 4.3 三条分享线(D4-3/4/5)

**线 A:角色包分享(社区 V1 唯一主线)**

| 环节 | 设计 |
|---|---|
| 发布 | 小程序内表单化打包 → 服务端过内容安全 → 过审上架。发布入口有门槛(绑定过设备或注册满 N 天,N 待定) |
| 发现 | 「内容库」页:官方精选置顶 + 分类 + 搜索 + 分享卡片二维码。**没有关注与粉丝**,曝光由官方精选位与热门榜分配 |
| 使用 | 详情页试听(**预生成音频**,发布时合成一次,约 0.5MB/分钟,40GB 磁盘存数千条无压力)→ 一键"装到我的手办" → 下次按键即用新人设(零固件依赖) |
| 反馈 | 点赞、装载计数、收藏;**评论 V1 不做**(评论是 UGC,审核面翻倍) |

**线 B:角色聊天记录分享(隐私最重,V1 不做;P2 开)**
总原则:**默认分享的不是"聊天记录",而是"名场面"——先脱敏、后授权、可下架,且明示已扩散副本不可追回。** ASR 全文目前明文落日志(Q-65 红线)——连日志都不该有的东西,更不能裸着进社区。四道闸:①选取;②**脱敏(默认最严)**:用户发言默认替换为「〔你〕」,正则+LLM 二扫,聊天里提到的第三方永不保留真名;③整理:「原文模式(只允许删减)」或「演绎模式(LLM 润色,强制打标"演绎内容")」二选一,防摆拍;④授权:明示公开范围、可随时下架、**他人已装载的副本不可追回**。产物:名场面卡片(分享图)+ **经历导入**(脱敏对话经 LLM 提炼为去身份 memory_seed)——**经历导入整体是待 Q-35 合规核实后裁决的候选**(§3.4 同一裁决项),Q-35 关闭前不上线;其记忆污染防护另挂 N-20。**线 B 内容下架后的存档范围与期限,列为 Q-35/Q-36 显式裁决项,法务关闭前不写"永久存档"**。

**线 C:共同探索(V2+)**:共同探索=官方骨架+社区血肉,优先"零文本 UGC":①投票共创(零审核);②模板化投稿(海龟汤按结构化模板,判定点写死);③晒图征集(图片审核)。设备触达只有两种:用户按键发起、用户配置的固定播报时刻——**空闲态主动播报需固件 G1,社区 V1 不依赖它**。理由:2 人团队的审核与产能撑不起开放式共创。

### 4.4 微信小程序 UGC 合规(D4-6)

> 微信内容安全接口的具体版本与参数**未联网核实,以微信官方文档为准**;类目资质与备案即 Q-32/Q-33/Q-34,列为社区上线前置检查。

- **D-E1 所有内容安全检测在服务端调用**(端上调用不可信),access_token 服务器统一管理;UGC 文本在"发布"动作上同步调用文本检测。V1 不上传音频到社区(分享的是 ASR 文本与预渲染试听)。
- **D-E2 三道机器闸+一个降速门**:①文本/图片检测接口(前置硬拒);②自建敏感词库(涉政/色情/未成年人/心理治疗话术/竞品导流);③LLM 预审打标(低=过/中=人工/高=拒);④降速门:人工队列积压超阈值即全局收紧为"先审后发"。
- **D-E3 审核 SOP(2 人团队)**:自由文本最少化;新作者先审后发(前 1~3 条)再转先发后审;每日 30 分钟固定审核台;留证(检测结果/风险等级/处理人/时间;**存档范围与期限挂 Q-35**);**总闸**:社区 tab 一键整体下线(半夜处置事故的兜底)。
- **D-E4 举报通道**:详情页+我的发布两处入口,固定枚举分类,SLA 48 小时,处理动作记台账并通知举报人,对举报人频控。
- **D-E5 未成年人保护**:不做未成年人向、禁儿童音;协议声明适宜年龄;**不采集年龄/学校等字段**;红线词库含未成年人相关词;不做任何私聊与互关。青少年模式依赖微信平台侧能力(Q-36;是否对含 UGC 小程序强制适配未核实,N-02 并案)。

### 4.5 冷启动(D4-7)

**答案不是"拉用户来发",而是"官方内容先当一个够好的内容库"**:①官方角色包 3~5 个(现全局默认人格演化为 1 个出厂核心+3~4 个差异化性格包);②官方外观 skins 若干(占位,待格式定稿与 SKU 同步首发);③周更栏目 ×1(建议语音海龟汤,预渲染音频);④玩法模板 ×2(「考你昨天说过的话」+故事接龙);⑤节点播报包(一年 4~6 次,预渲染)。**官方内容免费且常新,是"这个手办是活的"的证明**——没有它,社区功能上线日就是社区死亡日;周更是对"第三周急速衰减"(11 §0②)最便宜的对冲。

**冷启动顺序(写死)**:官方内容库先上线并独立成立 → 再开放生产者(线 A)→ 有真实互动存量再开线 B。

### 4.6 署名与激励(D4-8)

- **署名强制,激励是曝光的**:包内 author 字段详情页永久展示;**装载后的首次交互,手办口头署名一次**(挂 §2.7 首回合前置话术队列,不叠加);fork 强制显示"改编自 XX 的 YY"。口头署名同时是二次传播的种子。
- **V1 激励=非现金三件套**:曝光(精选位+热门榜)、身份(创作者等级+徽章,规则公示)、特权(内测资格)。**明确不承诺现金**(打赏/分成/稿费):微信支付需企业/个体工商户主体(备忘录;Q-30),iOS 虚拟支付另有限制(Q-37)。"创作者赠精力值"**V1 不做也不承诺**(Q-20 关闭后重审,N-19)。
- **反作弊最小集**:装载/点赞按账号+设备去重、同 IP 频控、榜单剔除作者自装载。

### 4.7 社区分期(D4-9)

| 期 | 内容 | 触发 |

## 5. 服务器架构与演进

### 5.2 模块划分(D5-2)

**六个模块 = 一个共享包 `figure_core` + 两个进程(+S3 抽取 worker),不做微服务。** 边界用包导入边界+表所有权强制:谁的字段谁改,跨模块只走对方 service 函数。

```
                        ┌──────────────────────────────────────────┐
                        │              腾讯云 2C2G 单机              │
 设备 ──wss:443(TLS-PSK)──> nginx stream(SNI 分流)                  │
                        │   ├─ 设备域名 → stunnel(PSK 终结)          │
                        │   │     → 127.0.0.1:8765 [voice-gateway]  │
                        │   └─ API 域名 → nginx http(TLS 终结)       │
                        │         → 127.0.0.1:8000 [api]            │
                        │   [memory-worker](S3 起,第三个 systemd unit)│
                        │   三进程共享 figure_core 包 + SQLite(WAL)   │
                        └──────────────────────────────────────────┘
```

**模块 × 进程归属(模块是代码边界,进程是部署边界;跨进程不走函数调用):**

| 模块 | voice-gateway | api | memory-worker(S3 起) |
|---|---|---|---|
| figure_core(pacer/pipeline/asr/tts/llm 客户端) | ✔ 设备语音回合全链路 | ✔ text-turn/预渲染试听 | — |
| 配置服务 | 读快照、连接时下发 | ✔ CRUD/激活/商店 | 读 |
| 记忆服务 | 热窗口读取+注入 | ✔ 面板 CRUD/回看 | ✔ 抽取与写入 |
| ai-proxy | ✔ 设备回合编排 | ✔ 文本回合/主动播报编排 | 仅 LLM 抽取调用,不经 TTS |
| metering | 回合预检+写事件 | ✔ 余额查询 | 写事件 |
| 社区服务 | — | ✔ 全部 | — |

- **跨进程调用通道**:设备语音回合**零跨进程跳**——ASR→LLM→TTS→pacer 全链路在 voice-gateway 进程内以函数调用完成,**不占、不动 1.2~2.1 s 预算**。api→网关的指令(#8 音量、#9 say、#14 激活、#10 播报配置)与主动播报任务走 **SQLite 控制表落库 + 网关事件循环轮询(约 1 s,仅在线设备)**——指令类非实时关键,1 s 时延可接受且不引入新常驻组件;该轮询时延与 text-turn 端到端延迟纳入监控与 N-15 复测项。
- **TTS 全局信号量载体**:进程内 semaphore 挡不住另一进程,改为 **SQLite 租约计数表**(`tts_leases`:holder/acquired_at,ttl 10 s 防僵死),figure_core 提供跨进程 acquire/release,三进程共用,默认 3;进程内另加异步包装减少每回合读写。若实测成为瓶颈再评估单点 broker(当前不引入)。

- **voice-gateway**:设备长连接与回合状态机、seq/abort 门控、pacer 下行、遥测与控制(音量 A4/电量 A5)、主动播报 outbox 消费、同设备会话互斥、优雅停机。**唯一**允许持有设备 socket 的模块。hello 的 dev 必须与设备登记表比对(sn 或预置别名命中方可接入;S1 起,M0 期校验退化见 §5.6 过渡方案);M0 用"PSK 持有+SN 登记+会话互斥"三道弱约束顶住 stunnel 拿不到 PSK identity 的缺口,彻底解法等 OTA(Q-50)后一起评估。
- **配置服务**:figurepack 存储/版本/审核状态;用户-设备-角色绑定与激活;连接时下发配置快照。**角色包是版本化不可变对象,设备激活的是某个 version,不是"当前草稿"**(设备端无屏,回滚=改指上一版本行);数据层=packs 聚合根 + pack_versions 每版本一行,characters.pack_version_id 指向具体版本(§5.3)。
- **记忆服务**:三层记忆的提取/检索/注入;对小程序暴露可见/可编辑/一键清空。**长期记忆不进计量消耗**。
- **社区服务**:平台内分享闭环;UGC 全链路过微信内容安全。
- **ai-proxy**:三种输入统一编排(设备语音回合/App 文本回合/主动播报任务);流程:计量预检→记忆注入→LLM 流式切句→TTS→交网关下发;**唯一**允许持有厂商密钥与连接的模块;TTS 全局信号量(默认 3,可配)。
- **metering**:精力值制事件溯源与余额判定;**只回答"允不允许开始、还剩多少",不建订单表**;先只记不限,实际限流等 Q-42/Q-19,开关就是 policy 表的一行。

### 5.5 部署形态与容量(D5-5/6/7)

**进程布局**:nginx(stream,`ssl_preread`,SNI 分流,443 复用——设备 PSK 域名不变、避免重烧,无 OTA 改地址=拆机)→ stunnel(TLS1.2 纯 PSK,挪进环回,配置死规定)→ voice-gateway;API 走 nginx http TLS 终结 → api(aiohttp,不引 FastAPI)。网关与 API 分两个 systemd 进程(故障隔离:API 崩了设备照聊)。安全组只开 22+443、禁 root 密码登录。内存预算约 210MB,2G 充裕。

**百炼 TTS 并发 ≈3 台:瓶颈对策(按性价比排序)**
1. **固定话术缓存(零成本,M0 就做)**:`NOT_HEARD_TEXT` 等兜底句预生成 PCM,命中直接走 pacer,不占 TTS 连接(原代码每次真调 TTS)。
2. **ai-proxy 全局信号量(默认 3,可配)**:满员排队 ≤1s 再走兜底话术("任何情况都出声",SERVER.md §6.3);排队时长本身是监控指标(容量不够的最早信号)。
3. 换厂商(火山代码在但从未真连,启用前必须重走验收,不作为容量承诺);多 key 池(百炼政策未核实+合规观感,排最后,Q-62)。
4. **第二道墙**:同时收发音频设备数 ≈ 公网带宽(Mbps)÷0.256;实例带宽未核实,买大实例前先用监控确认。
5. **百炼额度红线(M0)**:免费额度 2026-10-01 到期、无预警、TTS 仅剩约 170 句(备忘录 §六)——**额度监控+付费/充值切换预案必须进 M0**,否则服务会静默变哑。

**隐私整改(M0 红线)**:引入 `LOG_CONTENT=0`(默认),四处明文内容日志(session.py:185,223、ali_asr.py:79、ali_tts.py:189-191)改为只打长度/延迟;对话内容只进 chat_turns(带 expires_at+清空即删);journald `SystemMaxUse=200M`+logrotate。

**备份与纪律**:SQLite 每日 `sqlite3 .backup`→本地 7 天+COS 30 天,恢复演练列入 M0 验收(备份没恢复过=没有备份);配置即代码纳入加密备份;依赖锁;优雅停机(SIGTERM,在途回合 3s 收尾);监控最简形态=systemd 存活+结构化 JSON 日志+每日汇总脚本(回合数、首包延迟分位、错误率、TTS 排队时长、db 大小、余额分布),**不上 Prometheus/Grafana**。

### 5.6 分期 M0/M1/M2(D5-8)

**总原则:M0 的目标是"迁移+小程序够得着",不是"产品运营能力齐全"。**

**M0(三轨并行:A 云迁移 / B BLE 配网验收 / C 小程序资质)**

| 必须有 | 为什么 |
|---|---|
| 腾讯云迁移+三出厂值翻转+依赖锁 | `echo` 默认是"产品不可用但日志一切正常"的坑 |
| nginx SNI 分流+443 复用,设备域名定版 | 最后一次免拆机改地址的机会 |
| 日志脱敏+deploy/README 脱敏转 private | 隐私红线(Q-65)+信息泄露 |
| SQLite+users/devices/chat_turns 表+wx-login+claim+`/devices` 状态接口 | 小程序一切的地基(Q-61);落库顺带修掉"重启丢记忆" |

## 6. 竞品通性与我们的特殊性

### 6.1 A:用户真正在意什么(按证据强度排序)

1. **响应速度是第一差评,但它是及格线不是卖点**(01 §D【转述】)。迁国内后预期 1.2~2.1 s(D-08)——延迟只设门禁,不设宣传位。
2. **在意"像不像个活物",不在意"AI 聪不聪明"**(大模型接入已非壁垒,华强北 200 元套件【转述】;xAI Grok 伴侣功能收入只 +9%【转述】)——服务器端的价值在人格稳定性与内容。
3. **在意"不被偷听",物理承诺胜过隐私政策**("不按住,麦克风不工作"可写进包装盒)——每条数据流都要能回答"什么时候在录、录了存哪、能删吗"。
4. **在意"它记得我",且记忆应当免费体验**——芙崽把长期记忆放免费档永久免费,近 30 万台(公司 2026-07-13 Pre-A 公告口径,11 §1);记忆免费机制口径见 11 §0③/§4.2(华为官方页、对憨憨、与芙崽同源)。**付费点设在记忆上已被市场证伪。**
5. **在意付费公平,反感隐形收费与"解锁基本功能"**(315 实测 4 款隐形收费【转述】;精力值制付费档全部是"更多用量",11 §4.1)。
6. **在意服务连续性**(Moxie 停服变砖、2025 年复活后再次倒闭——11 §1 海外对照行与 §3 更正表;Jibo 2019 关服【转述】)——免费档必须让手办"断网也活着"(G6),"停服=本地模式+个人数据导出"是零成本信任资产。
7. **在意造型/系列/限定/换装——收藏与晒图是钱包**(支出结构硬件 41%/配件 33%/订阅 26%,01 §E【转述】;芙崽配件 ¥69–799,11 §1,E3 聚合页口径)。
8. **在意"具体时刻的具体缓解",不为"陪伴"这个抽象词付钱**(04 §6)。
9. 手办/潮玩人群的一手画像**完全空白**(Q-21)——对谁在意什么,目前只有桌搭侧证据。

### 6.2 A:市场怎么运转(标注已按复核意见拆分修正)

- **价格带**:**300–799 元是唯一被验证的高容量价格带**——芙崽基础款 399、华为憨憨 399/FZ1001(【已核实】11 §1,E1–E2);BubblePal 399 为 2024 首发价,**499 为后续媒体口径,11 §2 第 7 条明确"分属不同时点/打包方式,无法判定现价",仅定性**;优必选萌崽 499 为媒体口径(01 §C【转述】,11 §2 空白第 9 条仅述其订阅情况查无)。800–1999 段退货率最低(Ropet <4%,公司自报)但天花板明显;**"99–299 段价格战"【转述】(01 §C)**;**中间地带+强制订阅是死亡区,Jibo $899/Vector/Moxie $799 全灭【转述】(03 §B)**。
