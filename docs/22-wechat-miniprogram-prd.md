## 0. 一期小程序优先基线（2026-10-12）

**已确认**：首个客户端为微信小程序，Java为统一业务核心，一期包含角色生活与事件状态；已有角色形象与日常搭子关系方向沿用。角色可先在软件端体验，实体手办为后续联动载体；首次进入不强制购买或绑定设备。首页延续角色展示／可参与日常方向，聊天窗口和无缘由主动聊天不是首页主线。

**建议收敛的首个闭环**：游客查看角色 → wx.login建立平台身份 → 获得自己的角色实例 → 查看当前状态 → 完成一次明确可参与的基础互动 → 看到真实状态变化／结果 → 档案重读。此处只定义通用闭环；首个互动的触发、反馈、冷却、过期与记录内容仍需产品讨论，不把此前“招招手”演示自动升级为玩法需求。

| 承接面 | 首批应呈现的实际内容 | 完成证据 |
|---|---|---|
| 角色首页 | 小鲸形象、当前行为／状态、一个清楚的可参与入口及反馈 | 真机可交互，状态来自正式服务，刷新后可重读 |
| 生活／事件 | 当前可参与内容、参与后变化、等待／结束／错过状态 | 后端判定；重复／并发操作不重复结算，不靠客户端计时裁定结果 |
| 档案 | 当前角色与个人互动／事件结果；首页历史统一收纳至此 | 账号隔离；重启、重登及弱网恢复后仍一致 |
| 内容发现 | 真实已审核发布的角色／内容和素材版本 | 展示、装载与当前release一致；无占位资源包和假兑换 |
| 我的／设备 | 登录、个人资料、隐私、退出；设备认领／配网作为独立入口 | 登录、云端归属、WiFi配置、业务在线分别确认 |
| 管理后台 | 素材／角色／内容／事件定义的版本、审核发布与操作记录 | 与小程序消费同一权威版本；小程序没有另一套资产账 |

这是实施收敛建议，具体导航数量及页面设计仍待评审。下文旧五域／33页结构保留为历史需求与设计映射，不要求第一批逐页照搬；“商店”及说明性占位文案不再作为首批导航和产品内容基线。

3D展示目标保留。Web原型可运行不证明微信真机可用；需验证渲染方案、模型与纹理预算、首屏加载、旋转／触摸、内存和安卓／iOS微信表现。减面、压缩应派生新资产，保留原版脸部与纹理；性能不达标时提出等形象降级方案供评审，不自行改为粗糙替代模型。

设备玩法须等本地固件能力及云端回执联调；软件端事件与记录可以先验收。具体玩法、正式appid／域名、真机环境、3D性能预算为开发就绪待补项，责任人待指定。

## 1. 用户、目标与范围（历史基线，按§0收敛）

面向手办拥有者及浏览官方内容的潜在买家，解决开箱绑定、收藏档案管理、查看与纠正记忆、发现官方角色包、了解服务边界五类问题。

首发目标：进入产品无需强制付费；拥有手办的人可完成绑定与配网，再在首次真实对话后查看角色记忆。尚未绑定时可以浏览允许公开的内容，账号私有数据与修改操作需鉴权。匿名浏览范围及登录时机需在实现前明确。

| 本期目标 | 后置／待定 |
|---|---|
| 五域、开箱、绑定／配网、档案与记忆、官方内容、免费区、承诺、退出删除 | 支付／订阅等 Q-20；UGC、私信、关注不在本期 |
| 沿用现有 BLE，不新增固件能力 | OTA、音量／灯效控制、电池状态、额外按键手势 |
| 分享卡及统一 Web 承接 | 24h 试玩需服务端授权方案，不以静态页面宣称可用 |

“MVP1 页面目标”与后端 M0／M1 是不同维度：M0 地基落地后仍不代表记忆和所有 P0 页面业务可用。支付不作为本期验收的前置；兑换是否独立可上线仍需接口与权益方案确认。

## 3. 核心流程及失败恢复

| 场景 | 前置与主流程 | 失败／恢复 | 成功证据 |
|---|---|---|---|
| 浏览与登录 | 匿名进入允许浏览页；操作私有数据时完成微信登录 | 拒绝授权可返回；失效 token 提示重新登录，保留安全的草稿 | 登录结果与账号数据一致 |
| 绑定配网 | 鉴权→输入 SN／后续扫码→认领→扫描设备→加密配网→回查状态 | 蓝牙关闭／权限拒绝给恢复入口；密码错误 reset 后重试；断连重新握手；抢绑明确失败 | API 认领与设备成功联网两项分别确认，不相互替代 |
| 开箱认主 | 六步可跳过；命名、角色装载、签署按服务端结果完成 | 进度可恢复；命名／装载失败保留输入；无设备不能虚构设备出声 | 服务端角色、名字、编号与签署版本可重读 |
| 记忆管理 | 已有角色→列表→编辑／删除／封存 | 请求失败保留原状态；删除需明确范围；重复操作按后端契约处理 | 重载及另一端读取一致，封存与删除有区别 |
| 官方包装载 | 查看详情与免费边界→试听→装载 | 网络／音频失败可重试；权限与权益不足明确说明 | 角色与包版本实际入册 |
| 分享 | 用户选择公开资产→预览→生成图片／链接→分享 | 失败可重试；取消不发出；不带私人记忆 | 图片可保存，Web 可打开并正确回跳 |
| 退出／删除 | 用户查看删除范围→主动执行→显示结果 | 取消不改数据；失败不显示成功；处理中明确状态 | token 退出及相关服务端数据处理可复核 |

## 6. 历史实施顺序（一期由§0与J1基线更新）

## 2026-10-11 设备交互基线补充

新硬件基线为 upstream 69312fd、定制板 fw 0.5.0-idf61。详见 [App 与实体手办交互基线](app-device-interaction-baseline.md)，该补充优先于本文旧板实现描述；既有功能范围不因硬件更新自动扩大。

BLE 仅配 WiFi，后续业务走云端/WSS；WiFi 配置、业务连接和账号绑定分别确认。账号/归属/角色档案由云端持有，设备保存本地 WiFi/身份配置。采用“能量”呈现方向，但真实供电状态与未来玩法数值分开；USB 检测仅支持接电源表现，不证明正在充电。

当前无活动 20 分钟深睡（USB 下也执行），仅实体键唤醒，不能远程/BLE/定时唤醒。空闲状态尚不接受通用事件音频，hook 需要新增事件播放状态/命令/回执；音量有底层函数，滑杆仍缺命令/回执/NVS；双 OTA 槽仅为存储基础，下载/校验/切换/健康确认/回滚尚未实现。桌面保活、电池节能、定时唤醒、音量和 OTA 的具体批次待评审，不把讨论方案标成已交付。
