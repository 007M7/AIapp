# 首个角色内容稿：小鲸

> 2026-10-03 · 批次 1 讨论稿。用户确认项与建议分开记录；不代表正式素材、音色授权或玩法实现已完成。

## 用户已确认

- 角色方向：小鲸指向 DeepSeek 鲸鱼娘拟人二创形象。2026-10-04 用户已确认深蓝女仆版生成三视图的基础形象和实际比例符合预期，作为后续外观制作基准；不将此确认扩展为授权核验或硬件结构验收。
- 视觉基准：AIapp/assets/characters/xiaojing/2026-10-04/xiaojing-turnaround-v1.png；正面底图 xiaojing-master-front-v3.png。表情、动作及外观细节本轮补充，制作交接见同目录 MODELING-HANDOFF.md。
- 基础性格：嘴硬心软、贪吃爱摸鱼、会吐槽。
- 基础关系：日常搭子。有基础性格与关系即可，不先堆叠完整世界观与复杂关系设定。
- 内容扩展：后续丰富玩法承接不同内容；本轮先确定基础角色，不提前锁定全部玩法。

## 基础表达建议（尚待逐项确认）

| 性格 | 可采用的表达方式 |
|---|---|
| 嘴硬心软 | 偶尔嘴上嫌麻烦，但会认真回应；通过行动和具体回应表达关心 |
| 贪吃 | 吃饭、零食、加餐可作为自然出现的日常话题，不要求每次说话都玩梗 |
| 爱摸鱼 | 会开休息的玩笑，不以角色性格为由敷衍用户 |
| 会吐槽 | 轻松吐槽情境、偶尔自嘲；强度随语境调整，不把攻击用户当作个性 |
| 日常搭子 | 平等、熟悉、自然；默认用“你”，不默认主人称呼或恋爱关系 |

## 内容组织建议

基础角色承载性格、关系和常规语气；不同玩法承载各自的情境、剧情与任务。本轮不新建技术对象或接口。具体怎样装载、切换、退出和保存玩法状态，在各玩法需求确定后设计。

旧 demo 的“深海书简”“海里的灯塔”“今日贝壳”继续视为样稿，不因角色方向确认而成为正式首批内容。

## 下一步待讨论

1. 玩法核心循环及首个玩法待深入设计；首页采用 3D 小鲸展示，不设常驻聊天窗口。
2. “发现”首批内容是否先围绕这个角色展开，还是同时展示其它角色候选？
3. 确定具体视觉版本、名字与称呼；音色先试听候选再确定。
4. 确定首批真实可交付内容与相应素材。具体二创许可和商业使用条件沿用待办核查项。

## 第三轮：3D 展示与事件驱动体验（用户方向已确认）

- 首版放小鲸形象；用户建议用 Blender 制作 3D 模型，支持 360 度环绕观察。Blender 是资产制作工具，App 渲染方案、模型格式和性能指标尚未选定。
- 用户认为聊天窗口不必要，不以用户主动输入聊天作为主体验。既有文字回合源码可保留作验证工具／能力储备，不自动作为首页必选入口。
- 用户希望通过游戏事件或日常时间触发 hook，让鲸鱼娘开口。此处是事件驱动语音目标，不表示定时调度、后台播音、远程推送或实体设备主动播报已实现。
- 玩法需要深度设计，以长期可玩和用户愿意回来为目标；不以角色说一句话、点击喂食或签到代替完整玩法。
- 基础性格与日常搭子关系保持，玩法承接不同的情境与内容。

### 下一轮重点

1. 发声终端：App 内小鲸、实体手办，或按场景区分；先确定最重要的一种。
2. 日常时间 hook 的含义：打开 App 时匹配时段，还是用户未打开 App 时定时触发；后者需独立核对平台与设备能力。
3. 首个玩法的核心循环：用户做什么选择、有什么结果、小鲸如何参与、持久变化是什么、为何再回来。
4. 3D 展示资产清单：模型、贴图、材质；表情、待机／说话／玩法反馈动作按玩法确定后再制作。现有首页继续留空直至资产完成。

目前不制作模型、不启动新固件、不宣称上述体验已实现。本轮为产品讨论与记录。

## 第四轮：App 与桌面手办按场景配合

### 用户已说明

- 发声与互动由 App 和实体手办按场景配合，而非只选其中一端。
- 一期为桌面版；用户提出离开桌面后的远程沟通，以及鲸鱼娘“出门”等大致场景。
- 本轮“主人”为用户描述使用者的称谓，不自动替换已确认的“日常搭子”基础关系。

### 当前理解与待确认边界

- 桌面版沿用现有 USB 供电形态；不将“出门”直接解释为电池／便携硬件立项。
- 候选理解：实体手办留在桌面，用户出门后由 App 承接同一角色的 3D 展示、玩法参与与声音；这是场景建议，尚待用户确认。
- 远程沟通须区分远程玩法选择／事件回应、手机文字输入、手机与设备的实时音频桥接，不因场景描述直接承诺后两者。
- “出门”需确认是数字小鲸在手机中随行、玩法里的外出活动，还是实体携带；位置感知、日程读取、后台发声也没有自动纳入。
- 场景切换应保持同一角色与玩法状态，避免重复发声、重复奖励或产生两份独立角色；具体同步和播报优先级待设计。
- 下一步先确认“出门”的含义，再设计桌面／远程的核心玩法及事件触发点。

## 第五轮：陪伴来自持续生活与共同经历

### 用户已确认

- “出门”主要指数字随行和玩法中的外出，不以实体便携为一期目标。
- 用户以《旅行青蛙》作为玩法类比，强调陪伴感与真实感可以通过生活、玩法和事件体现，不依赖纯聊天。
- 该类比不等于决定复制其全部机制，也不等于小鲸所有玩法只能是旅行。

### 设计建议（待讨论）

- 以“小鲸日常＋外出经历”组织候选玩法：用户准备／选择→小鲸活动→发生事件→回来回应→记录或收藏→影响下一次活动。
- 日常生活是持续的基础场景；独自出游、数字随行等作为不同模式。角色性格在选择、行为、动作与声音中体现。
- 真实感来自事件前后连续、用户选择有影响、同一经历被记住；不声称虚构旅行为现实定位经历。
- 语音是事件反馈，不强制每个动作发声；离开 App 后仍能按玩法规则推进，回访时有一致结果，但具体时间推进和平台实现尚未设计。
- 留存验证关注再次参与、内容重复与选择意义，不先引入强制签到、断签惩罚或好感度数字。
- 原建议先讨论单一玩法；用户后续已明确须同时梳理纵向骨架和横向玩法，按第六轮修正。

## 第六轮：纵向与横向同时设计

用户明确独自出游解决时间纵深、日常参与解决横向丰富，两者同时设计，不能二选一；应参考多个产品，《旅行青蛙》只借鉴机制。已建立 [玩法参考与纵横设计](app-play-reference.md)，包含多产品官方来源、可参考机制和待讨论的两线关联。具体活动、行程时间及一期资源投入尚未确认。

## 第八轮：先收敛日常主线，暂缓具体玩法

用户指出 v0.1 已过早深入具体玩法，容易发散、难以确认。当前应先讨论并确定一条日常主线，再由主线承接纵向延续与横向扩展。

- 当前工作只回答：小鲸平时如何生活、用户如何参与、参与留下什么持续变化、声音在什么情境表达。
- 基础主线候选：小鲸在桌面／App 的日常生活→出现一件小事→用户可参与或略过→留下结果与经历→生活继续。此循环是建议，尚待确认。
- 旅行是纵向延续的扩展，厨房、解谜、布置等是横向玩法候选；它们不作为当前需要逐个批准的一期清单。
- 不先确定详细小游戏规则、资源经济、食谱、谜题、复杂世界观与每天强制完成的任务。
- 下一步形成简洁的日常主线描述和少量代表性情境，再讨论首页与必要内容；主线未确认前不继续扩展具体玩法。
