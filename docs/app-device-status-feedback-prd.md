# 设备状态反馈 PRD

> v0.2 · 更新：2026-10-27。跨端产品收敛稿，小程序优先，后续安卓／iOS复用。本文更新产品设计，不代表手机端、固件与服务端已全部实现。
> 正本：AI_figure/docs/product/；同步副本：AIapp/docs/。功能编号SF仅用于本文追踪，不替代项目正式需求编号。

## 1. 产品目标与已确认边界

让用户随时知道：手办能否互动、有没有开始听、是否正在准备回应、是否真的在回应，以及失败后如何继续。

- 语音继续采用半双工：按住实体键或已接通的屏幕按钮说话，松开后处理并回复；回复后回到待机，不自动开始下一轮录音。
- 首页仍以角色形象与可参与内容为主体，设备状态保持简短；角色生活状态和实体连接状态分别呈现。
- 用户无需查看串口或服务器日志即可判断日常可用性。详细技术信息放在设备详情的帮助信息中。
- 桌面联网待机、手机／场景触发实体回应继续沿用已有F01／F02方案；本轮收敛状态反馈，不将其一并认定为已实现。

## 3. 用户可见状态

| 主状态 | 出现条件 | 页面短文案 | 用户下一步 |
|---|---|---|---|
| 未添加设备 | 账号下没有可展示的实体设备 | 连接手办 | 进入添加／配网流程；仍可使用软件端角色 |
| 正在连接 | 已实际发起连接恢复，尚未确认服务就绪 | 正在连接 | 等待；失败后转入恢复提示 |
| 可互动 | 当前连接有效、互动服务就绪、设备空闲且状态可信 | 可互动 | 按住实体键说话，或使用已接通的手机／场景入口 |
| 正在听 | 当前输入端确认已开始本轮录音（实体麦克风或手机／电脑麦克风） | 正在听 | 按住说话，松开提交 |
| 处理中 | 本轮收音已结束，正在识别／生成／准备声音 | 处理中 | 等待；需要时按实体键打断并发起新一轮 |
| 正在回应 | 实体已实际开始本轮播放 | 正在回应 | 听取回应；可按实体键打断 |
| 等待状态 | 连接尚在，但未取得可信的最新执行状态 | 等待状态更新 | 刷新；暂停依赖空闲状态的手机操作 |
| 暂不可用 | 已确认服务未就绪或发生影响互动的故障 | 暂时无法互动 | 查看具体原因，按提示重试或重新连接 |
| 未连接 | 当前设备业务连接不可用 | 未连接 | 查看最后联系时间，按提示恢复 |

“已完成／已打断／失败／结果未确认”属于本次操作结果，与当前设备主状态分别记录。一次互动失败后，设备可能已经恢复“可互动”，失败结果仍应能看到。

状态依据以实体与服务端的真实确认及更新时间为准。生成文本、发送请求、服务端发完音频，分别不能直接等同于实体开始／完成播放。

## 4. 页面内容收敛

### 4.1 角色首页

- 主体：角色形象、角色当前生活状态、已有的可参与内容。
- 设备入口：一个状态图标加一句短状态，点击进入设备详情；需要用户处理的异常在这里给简短提示。
- 不把电压、RSSI、固件版本、协议名称和排查步骤铺在首页。相处历史仍进入档案。
- 角色“在休息”与设备“可互动”可以同时成立；不把角色动画当作设备已经执行的证据。

### 4.2 设备详情

| 分组 | 应展示内容 |
|---|---|
| 当前状态 | 主状态、本次互动进度／结果、适用的恢复操作 |
| 连接与服务 | 网络配置是否完成、设备业务是否连接、互动服务是否可用；账号归属另行确认 |
| 供电 | 已接电源／未检测到外接电源／未知；可信电量后续呈现，当前异常不显示百分比 |
| 最近信息 | 最后联系时间、当前状态更新时间；离线时明确是历史信息 |
| 帮助信息 | 设备名称／标识、固件版本、简短故障说明及必要的诊断信息 |

供电信息与设备主状态同时显示，例如“正在回应 · 已接电源”。配网成功不直接显示为服务可用，USB接入不直接显示为正在充电或已充满。

## 5. 手办本地反馈目标

| 场景 | 首批目标 | 当前情况 |
|---|---|---|
| 空闲可用 | 沿用低频轻闪，表达可互动 | 已有HEARTBEAT灯型 |
| 开始录音 | 开始收音前一次短提示，提示结束后再收音；手机同步“正在听” | 需补齐并核验；录音期间LED熄灭的现有规避保留 |
| 收音结束／处理中 | 明确离开录音状态，沿用等待灯光／提示 | 已有等待快闪及等待音效，产品含义需统一 |
| 实体开始回应 | 声音播放与手机状态一致，沿用播放灯光 | 已有播放常亮；手机端同步待补 |
| 连接／服务异常 | 可辨认的异常灯光，必要时一次短提示；重试期间不连续鸣叫 | 已有慢闪、连接和错误提示，需区分适用情境 |
| 结束／被打断 | 停止旧回应，回到实际的待机／新录音状态 | 已有物理按键打断，需验证跨端一致 |

具体短音素材、灯光节奏与等待提示频率在现板联调中核定。录音期间点亮LED曾影响声音，不把“录音亮灯”作为当前设计要求；灯灭也不能单独判定为没电或休眠。

## 6. 关键流程与恢复

1. 正常互动：可互动→按住键→确认录音／正在听→松开键→处理中→实体起播／正在回应→实体结束确认→可互动，并记录本次结果。
2. 打断：用户按实体键优先停止旧回应，页面跟随真实的新录音或待机状态；不把旧回合的迟到结果覆盖新回合。
3. 本次失败：没听清提示“没听清，请再说一次”；处理失败提示“这次没能回应，请再试一次”；播放中断提示“回应中断了，请重试”。恢复可用后才允许发起新的对应操作。
4. 断连：转“未连接”，保留最后联系时间；无法确认原因时不显示“没电了／睡着了”。只有收到明确睡眠记录时，详情可显示“上次进入休眠”。就近引导“按一下手办按键，等待连接”；远程操作给出不可执行结果。
5. 结果不明：提示“结果未确认”，先回查当前状态／结果，不自动补播或重发。用户主动重试需按业务规则建立新操作。
6. 返回页面：先核对最新状态再恢复可操作入口；刷新失败显示未更新，不保留失真的绿色“可互动”。

错误只在状态或操作结果发生变化时提示，后台自动重试不反复弹窗。语音服务故障应明确失败，不能静默把用户的原始录音当作AI回答播放。

## 7. 状态可信与刷新规则

- 角色状态、设备连接、语音会话进度、执行结果和供电分别判断，不以一个“在线”代替全部状态。
- 空闲、录音、处理、播放、恢复、异常均应能向手机端同步变化；忙碌期间仍可判断连接是否有效。
- 有连接但执行状态过期时显示“等待状态更新”，不把长回应直接判为离线，也不长期显示旧“可互动”。
- 页面重开、回前台、设备重新连接时主动核对；旧连接、旧请求和旧回合的结果不能回填新状态。
- 后续手机／场景操作只在归属、能力和当前状态允许时提供；实体没有完成回执时不显示执行成功。
- 正式刷新／过期／超时阈值需与固件、服务端联合契约统一。现有联调的2秒空闲上报、20秒新鲜度和5秒短鸣超时仅是联调值，不能直接套到全部语音状态。

## 8. 验收清单

| 验收项 | 应看到的结果 |
|---|---|
| 一次正常按键问答 | 手机状态与实体实际收音、等待、起播和结束一致 |
| 处理中／长回应 | 不因缺少空闲遥测而误报未连接；不显示虚构百分比或剩余秒数 |
| 按键打断后再说 | 旧回应停止，手机显示新状态，迟到回执不串回旧结果 |
| WiFi断开／服务不可用／恢复 | 各自有可信状态与恢复提示，重新连接后可重读 |
| 页面切后台再回来 | 先取最新数据；旧在线状态、旧结果不会覆盖新连接 |
| 准备睡眠／突然失联 | 明确睡眠记录与原因未知分别处理，不靠断线猜原因 |
| 电压异常／供电信息过期 | 显示电量暂不可用或未知，不显示0%、充满或虚假能量增长 |
| 对话链路故障／测试服务混入 | 不把回声播放冒充AI回答；只有正式互动能力就绪才显示可互动 |
| 未确认／重复请求 | 不显示虚假完成，不自动重复播放；结果可核对 |
| 实体反馈与声音 | 短音不进入录音，录音LED规避有效；本地灯音与手机状态一致 |
