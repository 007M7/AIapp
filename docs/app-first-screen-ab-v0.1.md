> 2026-10-06。基于 2026-10-04-1 研究批次的初步收敛稿。
> 用户授权：同步状态、收敛首屏方案并制作可点击原型。2026-10-06 两版 Web 原型已制作并通过桌面浏览器检查；尚未开展真实用户测试或冻结正式 PRD。
> 正本位于主仓 docs/product/；AIapp/docs/ 为同步快照。只针对 App，微信小程序另行处理。

## 1. 本轮要回答的问题

同一个角色与同一套基础互动，用户第一眼更容易被哪种呈现吸引、理解并主动操作：

- A：角色正在生活的空间。
- B：可观察、可互动的手办主体。

本轮只比较首屏呈现。具体旅行、厨房、解谜等玩法以及长期留存，不由这次首屏测试决定。

初步建议：两版均保留，先做等条件原型；不预设 A 胜出。研究推荐 A 优先只是验证顺序建议。用户强调通过形象吸引初期用户，因此 B 是同等重要的候选，不降为附属详情页。

## 2. 已确认的共同方向

- 初始关系是日常搭子；基础结构跨角色成立。
- 角色形象是第一眼主体，首页文字简短。
- 不以常驻聊天窗口为主体验；事件与动作可以引出声音，具体玩法后续设计。
- 时间纵深与横向玩法同时保留扩展空间，本轮不选某一条具体日常线。
- 允许错过，不引入惩罚、连续签到或关系数值。
- App 先形成独立体验；实体手办是玩法载体，硬件能力和 App 内容分别核验。
- 初期为无付费流程试验。商业化路径不作为本次首屏内容前置；公开传播或上线的素材条件仍单独核对。
- Blender 与实时 3D 是已提出并持续推进的资产方向。本轮不重问是否做 3D，也不把尚未验收的模型当完成素材。

## 3. 两版具体放什么

| 项目 | A：生活空间 | B：手办展示 |
|---|---|---|
| 主体 | 同一角色、同一姿态，处于极简桌边空间 | 同一角色、同一姿态，处于简洁展示背景 |
| 环境 | 桌面与一处背景，表达空间关系；不做完整房间装修 | 简洁背景与必要接触阴影；底座只在资产实际存在时使用 |
| 角色占比 | 首轮保持与 B 相同的屏幕占比 | 首轮保持与 A 相同的屏幕占比 |
| 可见状态 | 角色名字＋一个短状态，试验素材统一为“休息中” | 与 A 相同 |
| 主操作 | 一个“招招手”按钮 | 同一按钮、同一位置 |
| 直接操作 | 点角色，与按钮触发同一次回应 | 与 A 相同 |
| 即时反馈 | 角色看向用户，做一次简短回应动作 | 同一动作、时长与表情 |
| 字幕／声音 | 同一条短字幕；默认静音，可手动开启声音 | 完全相同 |
| 留下结果 | 原型若具备本地保存，记录这次互动，二级档案可查看 | 完全相同 |
| 底部导航 | 沿用手办／档案／社区／发现／我的 | 与 A 相同 |
| 设备入口 | 留在我的 → 设备，测试前不要求绑定 | 与 A 相同 |

A 的环境只回答“她处在一个地方”，不增加可点道具、额外活动或更多事件。B 的精致感来自角色展示与构图，不靠额外动作、材质等级或独有视角控制形成优势。

“招招手”是本轮操作发现性的试验动作，属于建议，不是一期唯一玩法或留存方案。换角色仍沿用操作 → 回应 → 可回看的结果，具体动作和语气由角色资产承接。

### 首屏结构草图

| 区域 | 两版共同内容 | A/B 差异 |
|---|---|---|
| 顶部 | 角色名字；简短声音控制 | 无 |
| 中部 | 角色主体；短状态 | 角色所在空间／展示背景 |
| 下部 | “招招手”主操作 | 无 |
| 底部 | 既有五域导航 | 无 |

首页不放：聊天输入框、研发解释、长说明、最近相处列表、资产统计、假价格、订单与订阅占位、未实现的设备在线状态。记录集中到档案，设备配置集中到我的。

## 4. 最短互动路径

### 第一次打开：先看到，再做一次

1. 打开手办页，直接看到角色，不经过登录、命名、设备绑定或长介绍门槛。
2. 用户自行点击角色或“招招手”。
3. 角色完成一次看向用户与回应动作；默认只显示简短字幕，声音手动开启。
4. 动作结束，恢复基础姿态；用户可直接离开，不追加任务或奖励弹窗。
5. 若试验原型已有本地保存，档案可重读一次互动结果。没有持久化时，只测试即时反馈，不写“已保存”。

原型目标：看到角色到完成回应，约 10–15 秒。该时长是设计目标，尚无实测结果。首次无提示观察窗口为 30 秒，不自动把未操作判为不喜欢。

字幕试验样例为“看到你啦。”，两版完全相同。正式小鲸语气可后续替换，本次避免因不同台词而改变比较结果。没有可用授权音频时两版同时使用字幕，不以未经核验的声音凑齐素材。

### 再次打开：先验证可重读，再验证生活延续

首轮原型只要求：设置保持一致、角色仍可观察互动、已真实保存的结果能在档案重读。一次点按不会凭空生成旅行纪念物或故事章节。

下一轮才加入同等的时间变化样例：两版均由“休息中”进入“翻看卡片”，开放同一个事件回应。用受控样例测试是否理解变化，研究员明确记录这是模拟状态；不宣称后台持续生活已经实现。

如果要观察真实 24–72 小时回访，必须先实现本机时间结算与持久化，并留存实际打开记录。测试者说“愿意回来”与实际回来分别记录。

### 无角色、加载与错误

| 情境 | 展示 | 可做什么 |
|---|---|---|
| 无可用形象 | 保留角色空位；不启用正式 A/B 比较 | 打开已有真实档案或稍后返回 |
| 资源加载中 | 两版同一占位与加载反馈 | 等待，不显示假互动成功 |
| 加载失败 | 简短“加载失败”＋重试 | 重试；已有可用立绘时两版同时降级 |
| 未绑定设备 | App 首屏照常可用，设备配置在我的 | 观察与互动；按需绑定 |
| 离线 | 仅使用确实缓存的内容与本地结果 | 本地动作；不显示服务端同步成功 |
| 静音 | 字幕与动作保持完整 | 手动开声，随时关闭 |
| 动作失败 | 恢复可操作状态，不写成功记录 | 重试 |

## 5. 360° 与渲染怎样处理

360° 是已提出的展示方向，独立验证它的增量价值。首轮 A/B 两版均固定同一视角；第二轮在选中的呈现里比较固定视角与可环绕观察，避免把“背景差异”和“可旋转差异”混成一次比较。

A/B 原型优先共用同一份已核对立绘或同一模型的预渲染素材。此选择只服务快速验证，不替代 Blender 精修、动画拓扑、绑骨、UV 与材质工作，也不裁定 App 最终运行时。

如果没有可信动作素材，两版一起改为同一组静帧表情切换，并记录限制；不得 A 用静图、B 用精修 3D 动画。当前模型未达到最终造型／变形验收，不能仅因有 GLB 就进入正式动画展示。

20 个角色版本的四视图是候选素材参考，侧背含 AI 补全。本轮只用一个角色完成比较，不把 20 个版本扩展为首版必须生产的内容量。

## 6. 做原型前需要准备的最小素材

| 项目 | 数量 | 使用范围／当前要求 |
|---|---:|---|
| 同一角色主图或同一模型渲染 | 1 套 | 两版共用；比例与配色先核对 |
| 休息姿态＋回应动作或静帧 | 1 套 | 两版共用；不能用不同动画质量 |
| 极简桌边背景 | 1 张 | A 使用，保持角色占比与可读性 |
| 简洁展示背景 | 1 张 | B 使用，不额外增加内容 |
| 主操作与状态文案 | 各 1 条 | “招招手”“休息中”，试验建议 |
| 字幕，音频可选 | 1 条 | 同一内容；无可靠音频则一起静音 |
| 档案样例 | 1 条 | 真实本地保存后展示；纯设计样例另标 |
| 空态／错误态 | 各 1 套 | 两版共用 |

不先准备 60–90 条事件、不扩建房间、不制作完整小游戏。研究报告中的运营内容量建议，不自动成为首屏 A/B 的制作门槛。

## 7. 快速验证与收敛规则

采用小样本定性测试，建议先分池记录纯 App 用户与手办／收藏用户；实际招募数量与参与者待安排。资料检索的画像不是本项目真实用户画像。

| 次序 | 测什么 | 操作／记录 |
|---|---|---|
| 1 | 第一眼理解 | 看 5 秒，问“你觉得这是什么、她在做什么？”逐字记录 |
| 2 | 操作发现 | 30 秒不提示，记录首个操作、位置、用时与是否需要提示 |
| 3 | 反馈理解 | 让用户描述“刚才你的动作带来了什么？” |
| 4 | 呈现偏好 | 两版看完，分别问角色存在感、好看程度、想继续做什么；不合成单一分数 |
| 5 | 声音需求 | 记录是否主动开声、是否能找到关闭、字幕能否看清 |
| 6 | 旋转价值 | 后续独立测试 360°；记录是否使用、想看哪里，是否妨碍操作 |
| 7 | 回访 | 有可运行持久化版本后再记录实际回访；与口头意愿分开 |

A/B 顺序交替，先 A 与先 B 都覆盖；同一设备、角色、动作、字幕、加载条件和事件数量。若出现明显加载或资源质量差异，先修原型，再比较呈现。

初步收敛规则：
- A 更容易被理解为有生活、用户能操作且没有被环境分散注意：可优先进入生活延续原型。
- B 更聚焦形象、用户愿意观察且能操作：可优先进入展示互动原型。
- 只喜欢看、无法理解操作：先修动作入口和反馈，不能靠添加更多玩法卡片填补。
- 两类人群偏好相反：按人群保留差异，不取平均、不马上把两版拼为复杂首页。
- 两版都缺少再次打开理由：说明主循环还需要设计，不能以首屏好看宣称留存成立。

以上是观察解释规则，没有统计显著性门槛；报告写实际观察到的人与行为，不声称“市场胜出”。
