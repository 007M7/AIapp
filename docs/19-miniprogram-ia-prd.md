## 1. 背景与目标

### 1.1 背景(一段话)

产品是 **AI 手办**(手办属性=购买理由主体,AI=附加值)。小程序是手办的**档案馆 + 编辑室**,并把**社区(营销主阵地)与商店(内容分发)**收进同一个端。服务端、社区、商店共用一套后端与资产模型(`14` 号的 `/api/v1`)。

### 1.2 目标

1. 开箱后 **≤2 步感知核心价值**:绑上手办 → 立刻"它记得你"的第一次证明(认主与第一张角色卡,不强制注册);
2. 资产的"可见面":记忆、角色、编号、契约**全部可查、可改、可删、可导出**;
3. 社区与商店在**零用户冷启动**下依靠官方内容独立成立;
4. 三端(小程序 / App / Web)同一套 IA 与同一份资产数据;
5. **设备侧 MVP1 已冻结**(零新增固件):设备只有两个动作——按住说话、播放中按键打断,与现状一致;**无音量/灯效等硬件控制项**;游戏、内容、仪式、设置等一切交互由服务器端驱动、在小程序里完成。

### 1.3 非目标(本期不做)

- 原生 App 开发另由 23 管辖：D-13 已有 iPhone MVP1，D-14 确认安卓同期；本文件只管小程序。Web 只做只读展示层;
- 社区 UGC 开闸(仅官方内容 + 双车道框架);任何私信/群聊/关注功能;
- 支付与订阅(等 Q-20 与企业主体);实拍图上传(等审核人力);
- 多台家户功能(等 N-29 裁决);**外观美术**不在本条线。

### 1.4 北极星与成功指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 激活(3 天) | 完成"绑定 → 首次对话 → 在档案里看到记忆" | ≥60%(待实测校准) |
| 回访(7 天) | 第 7 天打开过"档案"页的比例 | 建立基线(无行业基准可抄) |
| 首月付费意愿 | 无订阅状态下兑换/试用转化 | 建立基线 |

## 2. 用户与核心场景

- **主人群**:潮玩/谷子人群,女性为主,18-34 岁(`13` 号已复核);
- **四个核心场景**:① 开箱与认主(第一次);② 日常高频(说几句/听它说/看今天);③ 档案管理(记忆/角色/编号);④ 分享与浏览(社区/商店)。

## 3. 三端 IA 对齐(同一套信息架构)

### 3.1 五大域(三端共用命名)

| 域 | 小程序(首发·全功能) | App(后置·同构) | Web(只读展示) |
|---|---|---|---|
| **手办**(设备域) | 状态/今日/互动记录/绑定/设置(夜间静默为服务端策略;无硬件控制) | 同左 + **系统推送/蓝牙 OTA 通道** | — |
| **档案**(资产域) | 收藏册/记忆/角色圣经/出生证与契约/年历 | 同左 + **桌面小组件**(它今天的状态) | 角色公开页 `/c/:id`(圣经+编号验证,无用户数据) |
| **社区**(策展域) | 官方周更/精选/展示间/活动 | 同左(分享走系统分享面板) | 分享落地页 `/s/:token`、活动页 |
| **商店**(分发域) | 五架/永久免费区/订单/兑换码 | 同左 + **iOS 支付自由处理** | 商品展示页(引导回小程序) |
| **我的**(账号域) | 登录/订阅/通知/承诺页/退出与删除 | 同左 | 服务连续性承诺公开页 `/promise` |

### 3.2 对齐的三条技术原则

1. **API-first**:单后端 `/api/v1`(`14` 号 §5.4 已列端点骨架);三端不重复业务逻辑;
2. **资产账是唯一数据源**:角色/外观/纪念物/编号/契约只存服务端一份;客户端只做展示层差异;
3. **分享链路统一**:任何分享物生成的都是一个 **Web 可打开的卡片页**(`/s/:token`),页内深链回小程序——不做两套分享体系。

### 3.3 端差异仅三处(不得再扩散)

| 能力 | 小程序 | App | Web |
|---|---|---|---|
| 登录方式 | 微信登录 | 微信/手机号 | 无登录 |
| 支付(未来) | 安卓可内购 / **iOS 隐藏支付入口**(虚拟支付限制) | 双端自由 | 无交易,仅展示 |
| 推送 | 订阅消息(受限) | 系统级推送 | 无 |

## 4. 页面树(小程序)

### 4.1 Tab 结构(5 Tab,对应五大域)

```
TabBar: 手办 | 档案 | 社区 | 商店 | 我的
```

> 约束:微信小程序 **tabBar 页面必须放主包**;因此主包 = 5 个 Tab 首屏 + 基础库,**重代码(配网加密库等)全部下沉分包。**

### 4.2 完整页面树

```
pages/                          # ── 主包(Tab 首屏 + 基础);P0 = MVP1 必做,P1 = 可延后不阻塞首发
  hand/today                    # [P0][Tab1] 手办·今天:状态卡 + 今日小物 + 互动记录入口
  archive/index                 # [P0][Tab2] 档案·收藏册主视图("我的角色"≠设备管理页)
  community/index               # [P0][Tab3] 社区:官方周更 + 精选角色包
  store/index                   # [P0][Tab4] 商店:五架入口 + 永久免费区横幅
  me/index                      # [P0][Tab5] 我的:账号/订阅位/设置入口

packageDevice/                  # ── 分包A:设备域(含 BLE 配网,体重最大)
  pages/bind                    #   [P0] 绑定引导(扫码/SN 输入/认主引导)
  pages/provision               #   [P0] BLE 配网(并入现有 miniprogram/ 的 ble.js/prov.js/pb.js/x25519/aes_ctr)
  pages/settings                #   [P0] 设备设置:夜间静默(服务端策略)/解绑;无硬件控制项
  pages/manual                  #   [P0] 按键说明(按住说话 / 播放中按键打断 两动作 + 动图)

packageArchive/                 # ── 分包B:档案域
  pages/character               #   [P0] 角色详情(圣经/音色/相处事实/阶段)
  pages/memory                  #   [P0] 记忆面板(查看/编辑/删除)
  pages/memory-edit             #   [P0] 单条记忆编辑
  pages/seal                    #   [P0] 封存管理("这件事别提了")
  pages/assets                  #   [P0] 资产账(角色/外观/纪念物/编号,只增不减)
  pages/certificate             #   [P0] 出生证 + 契约卡 + 签署记录(可存图/可分享)
  pages/timeline                #   [P1] 年历(纪念日/第一次)
  pages/share-card              #   [P0] 分享卡生成器(收藏柜公开卡/开箱卡/年历 → 图片或 web 链接)

packageCommunity/               # ── 分包C:社区域
  pages/featured                #   [P0] 精选角色包列表(官方精选位)
  pages/detail                  #   [P0] 内容详情(预渲染试听/作者署名/装载入口)
  pages/gallery                 #   [P1] 展示间(官方陈列样例)
  pages/activity                #   [P1] 活动/主题周(V2 加投稿)

packageStore/                   # ── 分包D:商店域
  pages/shelf                   #   [P0] 分类货架(角色/外观/语音/事件/实物)
  pages/detail                  #   [P0] 商品详情(免费/付费边界明示 + 试听)
  pages/free                    #   [P0] 永久免费区(静态页:免费清单 + 边界说明)
  pages/orders                  #   [P1] 订单/权益(支付 V2 前为只读)
  pages/redeem                  #   [P0] 兑换码(实体→线上打通)

packageMe/                      # ── 分包E:账号域
  pages/promise                 #   [P0] 服务连续性承诺页(停服失效清单,照 17 号 §3.4)
  pages/settings                #   [P0] 通知/隐私/授权设置
  pages/exit                    #   [P0] 退出与删除通道(合规:一键退出)
  pages/help                    #   [P1] 帮助与反馈
```

### 4.3 关键页面要点(差异于普通 App 的部分)

| 页面 | 要点 | 依据 |
|---|---|---|
| `hand/today` | 首屏即"它今天"的状态卡:今日小物(当天首次对话时交付) + 它的小事 + LED 呼吸镜像;**禁数值条/进度条/红点** | 16 号"物感不是数值";14 号红线#3 |
| `archive/index` | 收藏册主视图(角色卡网格);空态文案引导"领养第一只手办" | 12 号 §2.2;API `GET /characters` |
| `archive/memory` | 三操作:查看/编辑/删除;**封存入口独立**("说一次永不再提") | 15 号 P0-1;17 号 A-S4 |
| `archive/certificate` | 虚拟物料主展位:出生证(名字栏手写)、契约卡(可存图)、签署记录 | 17 号 §3.1(虚拟化改造) |
| `store/index` | 首屏必须出现**永久免费区横幅**;付费商品详情页明示"哪些永久免费" | 消保委红线(15 号 §6.6) |
| `me/promise` | 承诺文本与 `17` 号 §3.4 逐字一致;含"停服后失效清单" | 17 号 §3.4 |
| `pages/manual` | 两动作说明:按住说话 / 播放中按键打断(包装卡+开箱第一句+本页三处一致);不再有敲击类手势 | 16 号失败模式"发现性为零" |
| `device/settings` | 夜间静默(服务端策略)、解绑、进入按键说明;**无音量等硬件控制项(设备侧 MVP1 冻结)** | v1.2 裁决;`18` v1.2 |

## 5. 分包方案

### 5.1 约束与预算

| 项 | 微信限制 | 本方案预算 |
|---|---|---|
| 主包(含 tabBar 页) | ≤ 2 MB | **≤ 1.5 MB**(留余量) |
| 单个分包 | ≤ 2 MB | 各 ≤ 800 KB(实测后调整) |
| 总包(主+全分包) | ≤ 20 MB | 预估 ≤ 5 MB(含预渲染试听音频须走 CDN,不入包) |

### 5.2 划分原则

1. **Tab 首屏留主包**,只放轻组件与请求层;所有列表数据走接口,不内置资源;
2. **重代码下沉**:BLE 配网加密实现(X25519/AES-CTR/protobuf,现 `miniprogram/utils/` 四文件)整体进 `packageDevice`;
3. 音频试听、分享图模板等静态资源**不入包**,走 CDN/服务端渲染;
4. 每个分包一个**领域**,与五大域一一对应,便于 App 端复用同名目录。

### 5.3 预下载与异步化

- 进入 `hand/today` 后 **预下载 `packageDevice`**(绑定是下一跳高频动作);
- 进入 `archive/index` 后预下载 `packageArchive`;
- 首屏 5 个 Tab 均为轻壳,深链进入分包页时用微信"分包异步化"承接(loading 态设计成"它正在醒来"的拟物动效,不出现默认白屏)。

### 5.4 现有 `mini_program` 分支代码的并入

- 现有 `miniprogram/`(19 文件 1433 行,BLE 配网)整体并入 `packageDevice`,作为 `pages/provision` 与 `utils/`;
- 其 `project.config.json` 的 `appid`(现为 `touristappid` 占位)在正式注册后替换;编译目标与基础库版本沿用其 `libVersion: 3.0.0`(需 ≥2.15.0,依赖 `wx.getRandomValues`)。

## 6. 关键流程

### 6.1 首次登录开箱仪式(虚拟物料链)

```
登录(微信,免注册可先用)
  → [装备须知页] 明示"永久免费 / 需付费"边界 + AI 身份标识
  → 绑定手办(分包A,可跳过,先领"虚拟手办"占位)
  → [认主] 填写名字 → 手办念出第一句自我介绍(依赖固件:普通回合即可,无需新固件)
  → [第一张角色卡] 首个角色包免费入册 → 生成编号 + 收藏柜公开卡
  → [契约签署] 虚拟契约卡(小程序内签署,设备无手势;可存图、可分享;物理版留零售)
  → 完成页:生成"开箱第一句话卡"(分享物)
```
每一步**均可跳过**;断点续做,不阻塞进入 Tab1。

### 6.2 绑定与配网

`hand/today` 空态 → `packageDevice/pages/bind` → BLE 配网(沿用现有代码) → 成功后回绑 → 引导进入 6.1 的认主步骤。

### 6.3 记忆管理

档案 → 记忆面板(列表/筛选) → 单条:编辑/删除/封存;**删除=硬删(用户主动),系统淘汰=归档**(`14` 号语义,待 Q-35 终裁)。

### 6.4 游戏与玩法(全部在对话回合内进行)

设备零新增手势。玩法由服务器端驱动:用户在普通对话里发起("想玩个游戏"),或服务器在对话中提议;题库、判定、节奏全部在服务端。小程序侧**不做游戏界面**,档案里保留"今天的互动"记录。

### 6.5 分享链路

生成图片/卡片(`archive/share-card`)→ 微信分享(卡片带 `/s/:token` web 落地页)→ 好友打开 web 页(角色公开信息,无用户数据)→ 引导"打开小程序"深链 → 小程序内一键试玩 24h(商店 B2 机制,需服务端试玩授权)。

### 6.6 兑换与购买(iOS 差异)

- 兑换码(`store/redeem`)全端可用;
- 支付:安卓内购入口; **iOS 隐藏支付按钮**,展示"内容转赠/兑换码"路径(微信虚拟支付限制);
- 任何支付入口旁必须出现"永久免费区"链接(消保委红线)。

### 6.7 退出与删除(合规)

`me/exit`:一键退出与数据删除通道(照 `15` 号 §6.6 落地矩阵);文案禁用"别离开我"类(15 号 §6.5)。

## 10. 验收标准(MVP1)

1. 首次开箱仪式全链可走通(可跳过、可断点),全程无支付/无注册强制;
2. 5 个 Tab 全部可达;`packageDevice/Archive/Community/Store/Me` 分包按预期加载;
3. 设备侧:**零新增固件需求(v1.2 冻结)**;仅剩既有收口验收(fw0.4 + F1~F4),不阻塞小程序开发;
4. 记忆面板:查看/编辑/删除/封存四操作可用;
5. 分享卡可生成、可存图、web 落地页可打开并深链回小程序;
