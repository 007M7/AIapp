## 1. 目标、参与者与范围

后台服务于角色素材生产、内容编辑、独立审核、发布、事件验证与运行排查。运营人员应能把一份素材逐步组织成可发布的角色／内容／事件，在消费预览中确认结果，查到谁在哪个版本上做了什么，并安全回退。

首版只写独立管理数据库和素材目录，不改生产用户、设备绑定、语音服务及模型原始文件。已有角色包／实例概念继续有效；管理版本是生产内容的来源，不建立第二套用户资产事实。浏览器 localStorage 不保存业务数据。

| 编号 | 用户场景 | 成功结果 |
|---|---|---|
| ADM-01 | 编辑上传角色图／GLB | 内容哈希、文件类型、体积和不可变素材版本可重读 |
| ADM-02 | 创建角色、正文和触发事件 | 每次保存产生新草稿版本；固定引用具体素材／角色／内容版本 |
| ADM-03 | 提交并独立审核 | 禁止审核自己创建的版本；拒绝理由可追溯；依赖通过后才能批准 |
| ADM-04 | 发布到预览／测试环境 | 自动收集审核通过的完整依赖；发布清单不可变；环境指针原子切换 |
| ADM-05 | 在消费预览执行事件 | 根据当前发布读取同一素材、角色和正文；生成本地执行结果及记录 |
| ADM-06 | 下架或回退 | 必须说明原因；只回到该环境历史发布；旧发布与审计不丢失 |
| ADM-07 | 管理管理员与权限 | 服务端鉴权；角色变更撤销已有会话；不能修改自身或禁用最后管理员 |
| ADM-08 | 排查与恢复 | 操作结果、版本关系、执行记录及审计分页可查；数据库备份可恢复 |

真实设备消费、生产 SSO、App 账号／资产、自动定时调度及社区用户投稿尚无实现前提；保留契约与页面边界，不伪造可用能力。事件中的时点、TTL 与 hook 是配置并可手动试运行，不等于后台调度已启用。

## 2. 页面与操作

| 页面 | 主内容 | 操作／关键状态 |
|---|---|---|
| 工作台 | 实际草稿、待审、发布与执行数量；下一步入口 | 无数据引导；刷新／失败；不展示伪造运营指标 |
| 素材 | 名称、类型、大小、哈希及版本 | 上传 PNG/JPEG/GLB；最多 32MB；原文件不覆盖 |
| 角色／内容／事件 | 列表、历史版本、结构化编辑与引用 | 保存新版本、编辑当前草稿、新版本复制；旧版本不可改 |
| 审核 | 待审版本、完整字段与依赖、作者 | 通过／驳回＋必填理由；自审、依赖未通过时禁止 |
| 发布 | 已批准版本、依赖清单、环境当前版本和历史 | 发布确认、下架、回退；并发指针变更要求刷新 |
| 消费预览 | 已发布角色素材、正文和事件列表 | 运行预览事件，显示返回文本与执行记录；不声称设备发声 |
| 操作记录 | 谁、何时、目标、动作、结果、请求标识和说明 | 游标分页；成功与拒绝均记录，不存密码或对话隐私 |
| 管理员 | 真实账号、角色、启用状态；预览账号另标 | 创建、变更角色、停用；仅超级管理员 |

工作台采用左侧稳定导航、右侧列表／详情／表单；危险动作通过带原因的确认框执行。空、加载、失败、权限不足、版本冲突、成功均有明确状态。页面按钮权限只改善体验，最终授权由服务端判断。

| 角色 | 查看 | 编辑／上传／提交 | 审核 | 发布／回退／下架 | 执行预览 | 管理账号 |
|---|---|---|---|---|---|---|
| 超级管理员 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 内容编辑 | ✓ | ✓ | — | — | — | — |
| 审核员 | ✓ | — | ✓ | — | — | — |
| 发布负责人 | ✓ | — | — | ✓ | — | — |
| 运行人员 | ✓ | — | — | — | ✓ | — |
| 只读观察员 | ✓ | — | — | — | — | — |

任何角色均禁止自审；超级管理员也不能绕过审批。首版为单组织，生产接入如有多租户必须补齐组织级数据范围，不能仅复用角色表。真实账号启停与权限变更留审计。

## 4. 主流程与恢复

上传素材 → 提交素材 → 独立批准 → 保存引用素材版本的角色 → 提交／批准 → 保存引用角色的内容 → 提交／批准 → 保存引用内容的事件 → 提交／批准 → 选择事件发布 → 自动带入依赖 → 消费预览执行 → 查看执行与操作记录。

内容修改产生新版本，不影响已发布清单；拒绝后另存新草稿再送审；请求失败保留表单；重复提交同幂等键返回原结果；并发保存或发布使用预期版本冲突保护。回退切换环境指针，不删除历史数据。下架后新执行被拒绝。

## 5. 版本与数据原则

素材版本固定哈希；角色版本固定素材版本；内容版本固定角色版本；事件版本固定内容版本；发布包固定所有版本及完整载荷；环境仅保存发布包指针。发布不得引用“最新版”。同一发布包中一个对象只能有一个版本，冲突阻止发布。

草稿、审核中、批准、拒绝是版本审批状态；是否正在发布由环境指针决定。历史批准版本可以回退使用。设备发送／接受／播放回执与管理预览执行分开：`preview_completed` 仅表示本机预览结果生成，`device_played=false`。

## 6. 验收与交付

上述八项分别对应领域／HTTP／浏览器验证。必须覆盖：独立审核、角色越权、未审批依赖、自审、重复写、幂等键冲突、并发版本冲突、冷却、发布后草稿不污染快照、下架拒绝执行、恢复后数据与审计保留、上传限制、会话及 CSRF。

本地模式只绑定 loopback，明确显示可切换预览身份；此入口不能部署到外网。真实账号使用密码散列和 HttpOnly 会话。生产发布需补 TLS／SSO 或 MFA、限流、资产安全扫描、异常告警、权限复核及用户／设备契约，责任人待指定。
