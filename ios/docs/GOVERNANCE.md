# iPhone 开发与交付治理

> 2026-10-03 · 延续 CONTRIBUTING 与主仓 02。产品正本归主仓，工程规格归 ios/docs；不另立决策编号。

## 1. 变更规则

先对应 23 的用户流程与验收，再改本目录工程规格，再改代码。页面文案、接口、业务状态、资产及承诺不能由代码反向定义。新范围回主仓 09 登记；Android 同期 D-14 不因聚焦 iOS 被撤销。

局部可替换实现可以推进并留取舍；架构冻结、商业方案、正式风险接受仍由所有者裁决。演示内容与真实结果在界面就近区分；不把 UI 按钮或示例数据当作能力已实现。

## 2. 合入与测试

检查顺序：本地 `npm run check` → `git diff --check` → macOS 自测／编译 → 模拟器页面状态截图 → 配网、音频、权限及业务联调。每一步记录环境、命令、提交、结果和未覆盖项。不能仅凭文件数量或截图文件非空判验收通过。

跨端产品／内容更新同步主仓与快照，CI 必须检查漂移。原型变化回生成器；本轮原型不变时不为凑视觉证据重出旧图。运行代码与构建工具变更需编译新源，旧成功 run 不替代。

## 3. 分发门槛

必须有新源编译成功、签名安装、页面状态和关键真机回归；业务功能需真实接口证据。正式对外分发前补齐账号认证、token 安全存储、真实删除与隐私说明、正式素材及适用资质；开发接入功能需隔离，不作为消费者设置流程。

本轮不推送、触发远端构建、签名、烧录或发布；先完成本地可审阅改动和证据。需要推进远端阶段时按仓库既有远端操作规则执行。

## 4. 状态汇报与责任

源码已实现、静态检查通过、编译通过、安装通过、真机通过、后端联调通过分别记录。责任人未知写待指定；不能替用户签验收。构建失败留日志，修改后重新验证，不沿用旧包。
